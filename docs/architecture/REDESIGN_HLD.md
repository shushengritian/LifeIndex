# Ocean 重设计 HLD 增量

当前：2.2.0/V4 已发布，后续本地修订按 ADR-0016、ADR-0017 实施。

用户已验收 G4 并授权实施；当前增量尚未发布。

## 基线与约束

保留 React、HashRouter、Dexie/IndexedDB、应用壳 service worker、静态 Pages。当前源码版本 2.2.0、数据库/备份 V4。不添加后台、账号、分析 或原生容器。原型只是视觉/交互依据，不将其内存控制器作为领域服务。

## 层级责任

| 层 | 变更责任 | 保持不变 |
| --- | --- | --- |
| `styles` / `shared/ui` | Ocean 语义色、图标、按钮、弹层、错误反馈、焦点 | 不访问数据库，不记录用户内容 |
| `app` / `pwa` | 导航顺序、草稿退出协调、更新互斥、URL Action 确认 | 既有路由和旧书签、显式更新、actionId 去重 |
| `features` | 已验收页面层级、历史入口、统计展示、分类管理 | 金额整数分、计时口径、健康/戒烟统计规则 |
| `repositories` / `domain` | 二级分类完整性和有效性，真实统计投影 | 原子写入、失败回滚、历史引用 ID |
| `db` / `backup` | 添加分类父级能力及新旧备份兼容 | 旧数据不猜分类、不删除、不自动覆盖 |

## 数据契约（已实施）

类别新增可选 `parentId`，只允许 finance 同收支域根分类作为父级，最大两层。旧分类缺少 parentId 仍是根级；账目继续只引用一个 categoryId。不创建虚构二级记录或重分配旧账目。

采用数据库 V4（categories 增加 parentId 索引）和备份 V4；旧 V1–V3 Dexie 声明保持，V3 升级仅增加索引，无破坏性行改写。扩大图标枚举须同时更新当前备份 schema，而历史格式必须冻结，不能让旧格式偷偷接收新父级字段。导入 V0–V3 先按原版本严格校验，再转换为 V4 根级；新版导出 V4，旧应用应明确拒绝未来格式。

归档父级只改变父级的状态；子级有效性为“自身未归档且父级未归档”。恢复父级不能自动恢复单独归档的子级。全部新增/改分类入口与导入完整性验证共享该规则；历史编辑允许保留原有归档引用，不能改选其他归档项。一级汇总包含直接记录及其子级记录，每笔恰好计算一次。

## 失败与回退

UI 只在事务成功后更新成功反馈；失败保留草稿。数据库升级失败不得清库重建；备份解析或关联验证失败不得开启覆盖事务。发布后不能简单回滚到只理解 V3 的代码，应前向修复或用户明确恢复兼容备份。第一批主题/导航未变更数据库，可独立撤回源码改动。

## 验证与发布

阶段 5 每批运行针对性单元/集成测试与源码检查；跨模块令牌变更需所有页面双主题浏览器检查。完整候选另跑类型、lint、格式、全测试、构建、E2E、迁移/备份故障注入和无障碍。真实 iPhone 系统专项单列，旧版本延期不沿用。无本轮 G5 授权不得推送发布。
