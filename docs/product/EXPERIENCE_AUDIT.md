# LifeIndex 产品体验审计

日期：2026-09-15。2026-09-16 记录：用户已确认 G1 审计与范围，进入 G2；具体交互/视觉仍待后续审核，不代表实现完成。以下保留审计时证据。

## 1. 结论与证据边界

LifeIndex 已有可用的本地数据层、离线框架、备份校验、主题、底部表单、日历和自动化测试，不是需要推倒重建的空壳。主要成熟度缺口是跨模块交互契约不一致、摘要和历史职责混合、部分已有数据缺乏完整浏览入口，以及异常/移动设备状态的验证不完整。优先修复任务完整性，再统一视觉，不能只换颜色和图标。

证据分类：A = 本轮直接观察（注明浏览器或源码）；B = 由实现推导的风险，未复现后果；C = 待设备测试或用户验证。源码观察不是用户研究；可读性风险不是已测得的用户失败率。

严重性：P0 = 已证实持久数据破坏/核心任务全面阻断；P1 = 用户工作丢失或重要任务缺少闭环；P2 = 局部效率、交互/视觉一致性问题；P3 = 可选美化。本轮没有确认 P0，不代表所有数据安全场景已覆盖。

## 3. 核心任务走查与操作基线

计数规则：从指定页面稳定状态开始，每次点击/选择算一次；文字输入单独列出，不将键盘逐键计数。条件确认和滚动另列。源码推演是结构基线，不是计时实验；后续 G2 用同一测试数据实测后再锁定目标，不预设“三步完成”。

| 场景 | 当前路径与操作数 | 证据与结论 |
| --- | --- | --- |
| 首次进入 | 今天 → 健康 → 新增 → 创建习惯，3 次到表单；输入后保存再 1 次 | 页面与源码：空状态能说明用途，但需要发现页头新增；直接任务入口待优化 |
| 新增账目 | 记账 → 新增 → 选分类 → 保存，3 次，另输入金额；选历史日另 +1 | 实际验证选日和打开表单；写入闭环由源码/测试支持 |
| 从今天记一笔 | 今天“记一笔” → 记账页“新增” → 分类 → 保存，4 次 | 源码：快捷入口只导航，没有直接打开表单；建议减少这一次重复入口 |
| 编辑/删除账目 | 列表编辑 → 保存，2 次另输入；删除 → 原生确认，2 次 | 源码/历史 E2E；保持选日与汇总一致纳入回归 |

| 新增体重/运动 | 对应加号 → 保存，2 次另必填输入/选择 | 体重表单实际打开；增改删由源码和测试交叉验证 |
| 健康历史 | 首页体重仅最近 3 条，运动仅最近 4 条 | 源码观察，未发现完整历史入口；旧记录仍在库中，不是被删除 |
| 习惯 | 新增 → 创建习惯 → 保存，3 次另输入；打卡/撤销各 1 次 | 源码/历史 E2E；统计在健康页内，14 周热力图不是独立详情 |
| 戒烟 | 开始计划 → 保存，2 次另输入；当日快照一次动作；吸烟记录需打开表单填写提交 | 源码/戒烟测试；历史、计划管理和结束确认另外计数，不压成一个指标 |
| 专注 | 空闲页输入事项 → 开始，1 次；取消/提前结束均动作 + 确认，共 2 次 | 实际验证输入草稿及切页丢失；启动、后台恢复和历史按源码/测试核验，无暂停 |
| 切换主题 | 设置中选主题 1 次；系统/浅/深 | 线上可见，持久化与失败回滚由源码/测试支持；本轮未更改用户主题 |

| 恢复 | 选文件 + 系统选择 + 预览 + 替换 + 确认 | 源码/测试：整库替换非合并；本轮未实际恢复用户数据，不报固定步数 |
| 应用更新 | 无草稿时立即更新 1 次；有草稿先完成或放弃输入 | 线上观察更新提示；代码保护主动更新，不等于保护普通导航 |

## 4. 问题登记

### EX-01：未保存输入离开保护不完整 — P1 / A（行为，置信高）

场景/证据：本轮专注输入“审计临时草稿” → 今天 → 专注，输入为空且没有离开确认。`src/pwa/useDirtyForm.ts:5` 仅登记更新保护，卸载即清理；`src/app/App.tsx` 路由没有统一脏表单离开契约。习惯编辑取消、体重目标取消也需纳入退出矩阵。

影响：未提交工作丢失，非已保存记录丢失，故 P1 而非 P0。建议：统一应用内导航、取消、关闭与浏览器返回的脏表单策略，保存中防重入；替代：同会话内恢复草稿，但不得擅自增加持久草稿字段。系统终止/刷新不能承诺绝对拦截，需明确限制。范围：所有表单与路由；业务字段不变，退出交互改变须 G2 批准。验收：每种退出方式覆盖干净/脏/保存中/失败四态，放弃须明确，保留能继续编辑。

### EX-02：健康历史浏览缺口 — P1 / A（源码，高）；实际用户影响 B

证据：`src/features/health/HealthPage.tsx:557` 体重 `slice(0,3)`；`:622` 运动 `slice(0,4)`；当前路由没有对应完整历史页。影响：记录增加后旧条目缺少常规查看/编辑入口，首页同时承担摘要和编辑。建议：摘要 + “全部记录”独立历史/编辑；替代：当前页展开更多，开发较小但页面更长。范围：健康 IA 和查询呈现，不新增指标/schema；这是新增浏览入口，必须 G1 确认范围。验收：用 40 条合成记录访问最旧项、编辑/删除后返回原位置，摘要正确，无伪造数据丢失结论。

### EX-03：风险动作混用原生对话框 — P2 / A（源码，高）

证据：`FinancePage.tsx:116,267`、`HealthPage.tsx:456,466`、`FocusPage.tsx:301,311,321` 使用 confirm；`SettingsPage.tsx:388` 分类改名用 prompt，`:119` 恢复用 confirm；戒烟亦有风险确认。影响：品牌、对象说明、焦点和处理态难统一，不是“所有原生交互都不应使用”。建议：统一应用内确认/短表单，明确“删除这条记录”“替换本机数据”等后果；替代：先保留低频原生确认并规范文案。范围：风险操作与分类；不改变删除、归档、恢复语义，不移除系统文件/分享界面。验收：取消零写入、失败可重试、连续点击不重复执行、危险按钮不默认误触。

### EX-04：公共底部表单没有统一关闭契约 — P2 / A（行为+源码，高）

证据：体重表单焦点在输入框时按 Escape 后 dialog 仍存在；`src/shared/ui/Sheet.tsx:5` 只收 title/children，无集中关闭处理；`CessationForms.tsx:24` 有独立 Escape/保存中保护。已有 inert/焦点返回应保留。影响：硬件键盘及跨模块预期不一致；触屏误操作影响仍待设备验证。建议：统一初始焦点、可见关闭入口、Escape、背景点击、焦点循环和滚动锁规格；替代：仅按统一契约修各表单，后续再抽组件。范围：公共 UI；不改变数据。验收：键盘/辅助技术可操作、取消不误存、保存中策略一致；移动键盘另需真机。

### EX-05：日历金额字号和截断风险 — P2 / A（源码，高）；可读性影响 B

证据：`src/styles/global.css` 的 `.finance-calendar small` 使用 8px、ellipsis；月汇总标签/值约 10/12px。影响：密集金额/大字体可能难读，不能据此声称用户已经看错金额。建议：保持紧凑月概览，明确每日净额/收入支出语义，优化数字层级，选日区域提供完整金额；替代：日历用简短金额标记，详情完整展示。范围：展示，不改汇总。验收：320/390/430 宽度、大额/负值/零值/长月份、两主题和放大；截断有完整读取路径，颜色不是唯一编码。具体字号在 G3 定稿。

### EX-06：首页层级与快捷入口重复 — P2 / A（页面+源码，中高）

证据：今天“记一笔”仅到 finance；健康首页多个大空卡与长说明，记录/习惯统计同页；专注空闲页事项、分类、备注同时展开。影响：主操作和回顾竞争注意力；实际滚动负担尚无用户测量。建议：今天直接启动明确任务，健康摘要/历史分层，专注次要输入渐进披露；替代：保持结构仅压缩文案/间距。范围：IA/入口，无新时间线、无专注暂停。验收：相同任务计数对比、关键状态可发现、返回保留来源；不能为少一次点击藏掉必要说明。

### EX-07：按钮/图标表达覆盖不完整 — P2 / A（源码，中高）

证据：`src/shared/ui/Icon.tsx` 已有导航和加号的统一 SVG，但编辑/删除/管理等未形成同一套映射；表单、行内操作、链接采用不同表达。2.1.1 已修正戒烟开始计划入口居中，不把旧截图当当前未修复证据。建议：建立主/次/图标/行入口/危险动作系统；替代：先统一高频操作，保留清晰文字。范围：视觉/组件，不改业务；验收：图标可辨认且有可访问名称、忙碌态不跳动、触点和对比度达标，非所有文字按钮改图标。

### EX-08：提交与错误状态尚未形成全应用契约 — P2 / B（中）

证据：新增表单多有 saving，戒烟有显式防重入；`FocusPage.tsx:175` 历史编辑缺少同等提交锁。习惯打卡仓储有唯一键，不能声称会产生重复记录。建议：列出各操作写入入口、忙碌/失败/重试契约并验证；替代：按风险逐项补齐。范围：表单/异步反馈；不改变成功语义。验收：延迟/失败/快速双击下最多一次有效动作、输入保留、错误可恢复；新增记录若需数据级幂等变更须单独评估。

### EX-09：真实移动状态证据不足 — P2 / C（待验证）

证据：现有移动 WebKit/axe/窄屏测试不等于 iPhone；尚未建立完整键盘、浏览器返回手势、主屏幕安全区、动态字体、后台计时和更新矩阵。建议：G4 原型自查、G5 产品自动化 + 用户真机清单；替代：明确逐项延期并获得本次授权，不能沿用旧豁免。范围：全应用 QA，不预判缺陷。验收：记录设备/iOS/显示模式/版本/步骤/结果，模拟与实机分栏。

### EX-10：历史文档和当前状态容易混淆 — P2 / A（文档，高）

证据：`V2_1_PLAN.md`、基线补充、`docs/operations/DEPLOYMENT.md` 中仍可见 2.1.0/待发布阶段描述，与当前 2.1.1 发布证据不同；`docs/architecture/LLD.md` 中统一放弃编辑状态描述未被全部表单覆盖。建议：新增当前审计入口与证据台账，后续实现同步修正文档现状；替代：另列偏差清单，不抹除历史。范围：文档治理，无业务变化。验收：读者能分清历史决策、实际实现、待批准方案；本轮已由四份文档和 PLAN 入口建立新阶段。

P3 装饰性动效、插画、全新品牌标志不进入必做范围；不以数量制造审计“问题”。
