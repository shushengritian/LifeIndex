## PRD 增量：首批验收条件

1. 记账编辑器始终有明确关闭和保存入口；长内容在中间滚动。关闭与 Escape 走同一草稿判断，写入时禁止退出/重复提交，失败保留输入并可重试。
2. 记录行只打开详情；删除位于编辑器内，确认后才写库，失败保留确认与原记录。
3. 保存其他日期仍保留原浏览日期，并提供「查看记录」；已有记录更新维持 ID，不添加重复行。
4. 主页「报表」为图标配短标签导航，进入继承浏览月；子页独立切月/收入支出，父日历日期不变，返回恢复原滚动。
5. 分类汇总一级与二级只计一次，金额整数分、比例按真实值；已归档历史不丢失。无记录不画数据点或折线，有记录范围中缺项日补零。
6. 失败读取显示错误，不能把读取失败伪装为零金额/无记录；报表不增加写入、预算、账户或导出功能。

## HLD 增量

React 路由下的父记账页保留已选日期与内存浏览上下文，报表为其只读子路由；数据读取仍经过 TransactionRepository / CategoryRepository 和 useLiveQueryState。日报及分类聚合为可单测的纯计算；React 图表消费结果。共享 Sheet 保持 Portal、背景隔离与焦点回归，受保护表单负责业务 dirty/busy 和确认状态。不改变服务工作线程、数据库或备份结构。

## 2026-09-21 滚动条统一约束

用户要求右侧滚动条问题不再重复。沿用 Ocean 设计，页面、报表、旧 Sheet、新编辑器内部滚动区及 Portal 后代统一隐藏滚动指示条；不再依赖触屏媒体查询，桌面预览与外接指针同样生效。只修改指示条表现，不使用 overflow:hidden 禁止滚动，不修改根滚动容器、导航定位或业务状态。

保留触摸、滚轮、键盘和焦点自动滚动；启动日志仅记录固定策略标识，不采集滚动位置。后续 I3–I5 必须复用此规则，不能单独恢复滚动条样式。新增短屏内部编辑器 E2E 检查，覆盖滚动到尾部、保存可见及关闭后导航存在；本次尚未运行该浏览器用例，列入 I6 必跑项。系统文件选择器/长按菜单不受网页 CSS 控制；iPhone 实际表现待真机确认。

## I3 首个实施增量（2026-09-21）

- 专注开始/提前结束移入计时区域，用统一 SVG 播放/停止图标与永久文字说明；开始仍走原生 form submit，运行结束仍需确认。取消降为次要操作，写入及待处理期间禁止重复结束。
- 自然到时的主读数改为待保存时长，明确保存成功才计入汇总；不再以 00:00 暗示记录已保存。时间事实仍来自已有 timestamp 与完成 hook，未改仓储和数据库。
- 专注详情复用结构化 Sheet，头尾固定、中段滚动；头部关闭与 Escape 共用原草稿确认。保留失败重试、删除确认和不可修改的计时事实。
- 今天移除大块记录引导，新增记账改为账目摘要旁 44px 加号，保留可访问名称“记一笔”；导航箭头、打卡符号改为统一 SVG。行为仍为现有单写入与导航。
- 沿用全局滚动条规则，没有新增局部覆盖或禁止滚动。

浏览器连接首次失败，启动本机预览后重试受到浏览器 URL 策略阻止，因此本增量没有新截图或真实几何/滚动验证，不声称短屏和 iPhone 通过。未提交、推送或发布。

### I3 第四个增量：返回上下文

最终检查：49 文件 / 258 项单元与集成通过，类型、改动文件 ESLint/格式、构建及 diff 检查通过。仍有原 Workbox 弃用警告。未提交、推送或部署。

今天习惯名称导航时记录来源 history key、习惯 ID 与非负有限 scrollY。仅内存 Map 保存最多 20 项，不写数据库/本地存储，不记录名称、ID、位置到日志。正常点击捕获，修饰键打开新上下文不捕获。关闭详情、页面返回与浏览器后退都能找到相同来源上下文；数据区加载结束后恢复焦点（preventScroll）和 window 滚动，一次消费，之后打卡刷新不抢焦点。习惯已不在今天列表时以可聚焦“健康习惯”标题兜底；刷新后上下文自然失效。

定点回归发现返回后立即打卡可能已写入但 live-query 未及时重读，成功写入后追加查询 revision 触发重读，不乐观改写记录，也不在失败时更新状态。定点 4 项通过：关闭返回、浏览器 POP、后续写入不重复滚动、暂停后标题兜底、失败重试。滚动使用 JSDOM mock 验证调用，物理滚动与 iPhone 仍未测；本轮未改 CSS 或隐藏滚动条规则。

### I3 第三个增量：习惯读取与写入入口分离

最终检查：49 文件 / 256 项单元与集成通过，类型、改动文件 ESLint/格式、构建与 diff 检查通过。首轮全量发现回执测试只等待 router 状态、未等待页面提交，改为等待实际日期回执后全量通过；生产保存行为未为测试改动。保留已有 Workbox 弃用警告。

今天习惯行的名称为详情链接，右侧为独立 48px 打卡/撤销按钮，使用 SVG 与可访问名称、aria-pressed。长名称可换行，操作区不压缩；不修改全局滚动规则。沿用 Impeccable 手动规范与 Ocean 现有语义色，不运行启动器。

路由 `/health/habits` 接受展示上下文 `habitId` 与封闭来源值 `from: today`，只从本地已有习惯匹配统计面板，不自动写入。来源不支持任意跳转 URL；其他来源默认返回健康。从今天打开的统计面板关闭后返回今天，页面返回入口也标明“返回今天”。未知 ID 不打开任何详情。写入仍由原单写入锁、仓储和失败提示负责，记录名称/ID 不写入业务日志。

定点 2 文件 / 3 项通过：打开详情零写入、关闭返回、失败不改变记录、重试成功、既有习惯 UI。滚动位置与触发点恢复仍待补齐；浏览器布局/真机未在本增量验证。未部署。

### I3 第二个增量：回执与读取失败保护

最终工程检查：48 文件 / 254 项单元与集成通过；类型检查、改动文件 ESLint、Vite/PWA 构建与 diff 空白检查通过。测试中误用的 locator `exact` 选项已改成精确正则，类型检查重跑通过。浏览器和真机验收不包含在以上结果内。

- 今天快速记账在仓储保存成功、草稿/写入保护释放后才返回今天；路由回执携带保存日期，取消不生成成功回执。日期仅供显示，不写日志。
- 今天显示“账目已保存 · 日期”与“查看记录”。用户点击后，记账页以 `financeViewDate` 初始化日历；不是业务写入参数。共享 `financeDisplayDate` 拒绝非字符串、非法日期及小于 1000 的年份；缺失或无效上下文回退今天。无数据库/备份结构改变。
- 专注编辑器从列表的 ready 分支移到页面稳定层，并在打开时快照分类。后台读取失败不卸载编辑器，不丢字段、dirty guard 或删除确认。保存和删除仍调用原仓储，成功后才关闭。
- 新增真实 fake IndexedDB 集成检查：异日保存→今天回执→显式查看对应日历，全程只写一条账目；非法日期兜底；后台历史查询失败后草稿与放弃确认仍在。定点 2 文件 / 7 项通过。本轮未新增 CSS，不改变统一滚动条策略；浏览器与 iPhone 专项仍未测。
