研究日期：2026-09-28。负责人：`/root/ui_research`。阶段：M1 / 第一轮方向讨论输入；研究结论不等于设计冻结、原生 App 实测或上线验收。

## 研究边界与结论

LifeIndex 服务于个人在 iPhone 上快速记录、随后回看生活的场景。4.0 覆盖今天、健康与习惯、专注、记账与报表、设置与备份；本地优先、IndexedDB 主数据源、应用外壳缓存和隐私要求保持不变。依据为 [4.0 执行约定](https://github.com/shushengritian/LifeIndex/blob/cea0d8b53c3686cdefb2b99f824d80e08bda5d8c/docs/project/V4_EXECUTION_BRIEF.md)、[产品基线](../../../LifeIndex-Project-Baseline.md)、[当前 UI 契约](../../development/CURRENT_UI.md)。

研究建议优先验证设计总监的 A「日序」：首页先让人完成当下动作，再呈现当天真实记录，最后进入各领域回看。它需要改变内容顺序、录入结构、状态反馈与返回行为，不能只替换颜色或按钮皮肤。

“超过市面上 80% APP”是品质愿景，本研究不推算市场百分位。七款目的性样本、官方宣传和内部评分不能构成市场排名证据。结果要由固定任务前后比较、完整状态、独立设计审查、无障碍与离线测试证明。

### 证据分级

- **E1 官方行为说明**：实际打开并阅读官方产品页或支持文档，能够核验作者声称的操作、信息架构与状态。
- **E2 官方视觉材料索引**：实际核验官方页面存在的截图/演示及其文字描述；仅看到图片地址、alt 或视频嵌入时，不声称完成像素观察。
- **E3 浏览器视觉观察**：通过浏览器查看官方页面或静态图；记录观察者与证据路径。它仍不能证明原生手感、性能、无障碍或失败处理。
- **E4 原生实操/任务测试**：本研究没有安装、登录或操作七款原生 App，因此无此级证据。

研究代理的浏览器发现返回不可用，按文档检查后可用列表为空；因此 E1/E2 使用网页工具核验，关键 E3 由主代理的可用浏览器补充。不存在为获取样本而付费、注册外部账号、访问真实个人记录或复制品牌素材的行为。竞品图只作研究证据，不能直接作为 LifeIndex 发布资产。

## 七款官方参考

以下全部于 **2026-09-28** 核验。事实、借鉴建议和不能推断的部分分别列明。

### R01 · Things：今天的组织与渐进展开

**官方来源：**[功能说明与演示](https://culturedcode.com/things/features/)；[官方 iPhone Today 图片](https://static.culturedcode.com/things/videos/2017-05-18-website-videos/2-today-iphone.png)。该功能页与图片属于历史设计材料，不将其标为当前最新版界面。

**实际核验（E1/E2）：**官方说明将日历事项与待办组织到 Today，并以 This Evening 区分稍后的事项；打开待办后再提供备注等细节。Magic Plus 支持点击创建和拖动定位。页面有 Today 的 iPhone 图与操作演示入口。

**可借鉴：**首页围绕当天上下文编排；记录表单先突出核心值，再展开可选信息；新增动作保持位置可预期。图像参考重点是日期、分组、条目和完成控件之间的层级，而不是复刻蓝色或白纸外观。

**LifeIndex 取舍：**支出、体重、运动保留明确快捷入口；可选备注不抢占第一视觉层。今天仍是聚合页，不因参考 Things 就新增待办、日程或拖拽排序系统。

**不能推断：**未实操拖拽，不能宣称其成功率、耗时或 VoiceOver 体验；历史官方图不证明当前版本的全部样式。

### R02 · Oura：当下与长期分层

**官方来源：**[How to Use the Oura App](https://support.ouraring.com/hc/en-us/articles/42987005571859-How-to-Use-the-Oura-App)；[官方 App 视觉展示](https://ouraring.com/membership?trk=article-ssr-frontend-pulse_little-text-block)；[官方改版说明](https://ouraring.com/blog/new-oura-app-experience/)。

**实际核验（E1/E2）：**帮助文档将 Today、Vitals、My Health 分为当日信息、指标集合和长期回看。Today 有快捷指标、待处理事项与近期事件；Vitals 可进入详情并切换日期。官方展示页包含首页、Vitals 与 My Health 的界面图描述；改版说明是历史背景材料。

**可借鉴：**首页回答“现在有什么值得处理”，领域页回答“这个指标如何变化”；摘要提供明确详情路径；数据不足需要独立状态。

**LifeIndex 取舍：**正在运行的专注放在当前行动区，已保存记录才进入历史与统计。保留领域页稳定入口，避免内容动态排序导致用户每次找不到东西。

**不能推断：**LifeIndex 没有 Oura 传感器数据与算法，不能借用健康评分、恢复能力、疾病提示或个性化医疗结论；展示图和帮助文档不证明真实响应速度。

### R03 · Gentler Streak：反馈温度与时间尺度

**官方来源：**[Gentler Streak 产品页](https://gentlerstories.com/gentlerstreak)；[官方 Activity Path 图](https://framerusercontent.com/images/hwkj8O8B3ZzRQiQUSjm9YAM58.png?height=1614&width=900)。原 `gentler.app` 当前重定向至前述官方页面。

**实际核验（E1/E2）：**官网强调允许休息的持续记录，展示 Activity Path、当日状态以及多个时间范围；状态可表达休息、生病或受伤。Activity Path 图的官方描述包含路径、角色与运动完成后的反馈。

**可借鉴：**让完成反馈简短而具体；日、周、月视角服务不同问题；空白或休息不使用羞辱性文案。视觉研究关注图形、指标和一句解释的配合。

**LifeIndex 取舍：**习惯显示当天真实完成情况，未完成不等于“失败的人生”；健康页提供明确记录入口与可解释的趋势。装饰图若使用，必须是原创或有清晰许可，且在无图时不丢失信息。

**不能推断：**不能由官网文案推导真实留存、减压效果或运动处方有效性；不复制 Yorhart 角色、Activity Path 造型或训练算法。

### R04 · Copilot Money：从摘要下钻到记录

**官方来源：**[产品展示](https://www.copilot.money/)；[Dashboard 说明](https://help.copilot.money/en/articles/6045480-dashboard-tab-overview)；[Cash Flow 说明与嵌入演示](https://help.copilot.money/en/articles/9682232-cash-flow-tab-overview)；[官方 Cash Flow 演示地址](https://www.youtube.com/watch?v=3VCyD4B3Cuw)。

**实际核验（E1/E2）：**Dashboard 区分图表、待审阅交易和月度净收入；Cash Flow 将收入、支出、净收入分开，支持范围切换及分类/交易详情。iOS 柱图单击查看数值、双击下钻是文档明确说明的行为。产品页有金额、分类和流水等视觉展示；视频入口已发现，未声称看完视频。

**可借鉴：**一个突出主值、相邻辅助值、下方解释图形和明细；每个数字有明确时间范围；统计与明细之间可追溯。

**LifeIndex 取舍：**记账首页优先显示本月支出与收入，报表展示真实记录的范围和明细。图表下钻给出可见按钮，不把双击或悬停作为唯一入口。没有预算数据时不显示“还可花费”。

**不能推断：**不把产品图中的自动分类、银行连接、预算、投资或待审阅机制视为 LifeIndex 已有能力；不能推断其双击设计适合我们的低频用户。

### R05 · Streaks：完成状态的辨识与回看

**官方来源：**[Streaks 官网](https://streaksapp.com/)；[官方统计页图](https://streaksapp.com/images/iphone-stats.png)。

**实际核验（E1/E2）：**官网说明任务可按指定日安排，完成延长连续记录，可查看任务统计；页面包含任务及统计界面图。官网正文不足以确认手机完成动作究竟采用单击还是长按，因此本研究不作该操作结论。

**可借鉴：**习惯名称、图标、完成状态与历史视图的连接；当天是否完成应当一眼分辨；少量重复结构帮助形成操作预期。

**LifeIndex 取舍：**保留仓库已有的一触签到与撤销，详情和写入为分离控件，避免点开习惯就被记为完成。完成反馈不得依赖颜色；固定目标触控面积、明确可访问名称与写入中的防重复状态。

**不能推断：**连续天数不是习惯效果的因果证据；不引入断签羞辱、奖励货币或必须长期保持满格的评分压力；官方统计图不证明算法与本项目日历语义一致。

### R06 · Apple Health：摘要、趋势、原始记录

**官方来源：**[查看健康数据](https://support.apple.com/en-mt/guide/iphone/iphe3d379c32/ios)；[健康数据介绍及 Summary 图](https://support.apple.com/guide/iphone/intro-to-health-data-iphbb8259c61/ios)。

**实际核验（E1/E2）：**官方指南明确区分摘要固定项、Highlights、Trends 和分类详情；可以点图表查看更多信息，在详情切换时间范围、手动新增及查看记录。介绍页含 Summary 界面图，官方描述列出了固定区域中的健康项目。

**可借鉴：**摘要不必铺开所有指标；图表同时提供时间范围与数字解释；趋势详情仍能回到原始记录。

**LifeIndex 取舍：**健康主屏采用体重、运动、习惯的不同内容结构；体重折线、运动时长、习惯日历各自使用匹配的数据表达，避免三张完全同构的大卡片。空趋势提示需要更多记录，不用虚构示例曲线冒充真实统计。

**不能推断：**PWA 不能因外观近似就拥有 HealthKit、自动传感器接入或医疗记录；未验证 Apple 原生图表触控和辅助技术行为，不照搬其删除手势作为唯一入口。

### R07 · Apple Clock：清楚的计时状态与控制

**官方来源：**[设置计时器及界面图](https://support.apple.com/guide/iphone/set-timers-iph8241d6b2a/ios)。

**实际核验（E1/E2）：**官方指南展示添加计时器的页面，说明自定时长、可选名称、开始、最近使用、暂停和恢复等操作；其配图描述包含时长设置及最近计时器的启动入口。

**可借鉴：**时间读数是主角，开始/暂停/恢复随状态替换；固定常用时长避免重复填写；正在计时与历史配置清楚分离。

**LifeIndex 取舍：**专注页突出剩余、已用与目标，次要配置退后。现有专注只有运行与完成状态，借鉴 Clock 的控制层级，不引入真实暂停；“收起计时”与“返回正在运行的专注”必须明确表示时间仍继续。结束保存的成功与失败均为显式状态，只有完成且保存的数据进入统计。

**不能推断：**原生 Clock 的后台计时、通知、声音和锁屏表现不能直接承诺给 iPhone PWA；LifeIndex 要用实际恢复与时钟测试证明行为。

## LifeIndex 的独有方向与全页面策略

机制句：**同一份本地生活记录，让今天的动作与之后的回看相互连通。**

| 页面 | 信息的主角 | 需要重构的体验 | 禁止用来填充高级感的内容 |
| --- | --- | --- | --- |
| 今天 | 此刻可做的动作、今日真实记录 | 首屏直接录入；运行中专注独立；习惯一触完成；历史入口有清晰去向 | 虚构生活总分、随机名言大横幅、占据首屏的纯装饰 |
| 健康 | 体重变化、运动、习惯各自语义 | 三种数据采用不同结构；新增与查看分离；日期与缺失状态明确 | 没有数据的示例曲线、未经支持的健康判断 |
| 专注 | 当前会话与时间 | 预设时长、开始、收起/返回运行中会话、结束保存、失败重试 | 把收起称为暂停、影响读数的背景动画、假后台通知、把未保存时长计入成绩 |
| 记账 | 选定范围收支与流水 | 金额优先的录入、分类选择、明确保存、取消保留上下文、报表到明细 | 无预算却出现预算余额、靠颜色区分收入支出、只支持双击下钻 |
| 设置与备份 | 偏好和数据安全操作 | 明确文字入口、分组行、恢复预览与确认、错误可恢复 | 假账号头像、暗示云同步的图标/文案、默认暴露破坏性操作 |

原创视觉语言由设计总监统一选择。研究支持用字体层级、节奏明确的分组、比例有差异的信息区、统一图标和组件状态实现品质；不建议给所有内容套同等尺寸与同等边框的卡片。背景图、插画或纹理必须有用途、可离线、对比度合格、有降级方案及来源记录。

### 轨迹的数据语义

已只读检查 `src/shared/domain/types.ts` 与 `src/features/today/TodayPage.tsx`：现有实体有业务日期字段，今天区分加载/失败/就绪状态；习惯查看与写入分离；专注运行中与完成数据分开查询。4.0 应保留这些真实责任，不因新布局丢失它们。

- 以实体保存的 `localDate` 归属业务日期，不把当前设备时区重算值冒充原记录日期。
- 交易和运动用 `occurredAt`，体重用 `measuredAt`，习惯用 `completedAt`，专注结合 `startedAt`/`endedAt` 与保存状态解释；不得用通用 `createdAt` 冒充所有业务发生时刻。
- 没有充分时间语义的项目只显示日期或记录顺序，不制造精确到分钟的“人生时间线”。跨日专注如何计入当日范围需架构契约明确。
- 读取中、读取失败、就绪但为空分别呈现；某一领域失败不能把该领域显示为 0，也不能阻断其他已成功领域。

| T2 | 首页记录体重 | 同上；单位清楚、合适数字键盘、与查看趋势分离 |
| T3 | 首页记录运动 | 同上；类别和时长易辨识，必填和可选信息有先后 |
| T4 | 首页开始默认时长专注→收起计时→返回运行中的专注 | 时间持续运行；收起不叫暂停；返回同一会话，不重复创建 |
| T5 | 今日习惯完成/撤销 | 可见条目上一触完成；撤销可发现；查看不能意外写入；防重复提交 |
| T6 | 首页查看当月支出报表并回原浏览上下文 | 月份语义明确；图表可解释；返回恢复来源、选择和适用的滚动/焦点 |

每项记录：点按数、滚动次数、首个操作所在视口位置、是否依赖猜图标或隐藏手势、到达结果、返回上下文。T1–T3 单独记录进入编辑器的点按数；耗时测量在固定环境下重复采样，不能以代理阅读或思考耗时代替用户操作时间。

T4 在正式测量前由独立审核纠正语义：3.3 无真实暂停，仅收起且时间持续。主代理据此冻结上表，不新增暂停状态，也不把收起/返回称为暂停/恢复。

全部任务不得出现实质退步，至少三项减少步骤或消除事先记录的体验缺陷。备份、导入、流水编辑、删除、异常恢复等仍属于完整验收，只是不占这六项效率基线。没有真实使用者测试时，只能声称清晰标签和固定脚本通过，不能声称已证明人群层面的发现性或满意度。

## 第一轮真实讨论记录

输入版本：研究初稿 R1.0；设计总监候选 A「日序」、B「坐标」、C「生活书页」。这是正式启动后的讨论，准备阶段任务书不计入轮次。

### 三个方向的研究评价

| 方向 | 研究员观点 | 保留的长处与需验证的风险 |
| --- | --- | --- |
| A 日序 | 优先进入可操作原型验证 | 与高频记录目标一致；但不能把“待做”扩大成新增任务系统，也不能让叙事挤走快捷录入 |
| B 坐标 | 作为对照方案 | 适合领域回看，指标层级直接；容易出现无依据评分、空数据下大面积占位，首页记录动线可能变长 |
| C 生活书页 | 不建议作为默认首页主结构 | 日期分节有助回看；但时间线必须有真实语义，记录触发器不能成为隐藏所有操作的黑箱 |

A 可吸收 C 对日期分节和记录连续性的纪律，但不能拼接两套材质与组件风格。B 的数字排版可用于记账与趋势详情，不能把首页全部改成统计仪表。
