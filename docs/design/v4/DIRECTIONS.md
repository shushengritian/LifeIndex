# LifeIndex 4.0 · 第一轮设计方向

日期：2026-09-28。设计负责人：`/root/design_director`。版本：R1.3，已吸收本轮研究与独立审核的具体异议，**等待独立审核复查，不代表设计冻结或进入生产实现**。

## 最新范围修订

用户在本轮明确要求“**不用考虑旧版，直接设计新版**”。4.0按独立的新产品体验设计；旧版布局、组件、导航、操作步数和状态模型不再限制方案，也不再要求“全部不退步/至少三项优于3.3”。六项核心使用任务继续作为新版覆盖清单，以自身可发现性、效率、完整性和真实状态验收。既有数据安全、本地优先、零新增工具费用、三轮独立评审与发布验收边界继续有效。此前量测只属于过程事实，不作为方向优劣或放行门槛。

用户进一步明确：至少三轮讨论，不要求第三轮必须定稿；关键问题未消除时继续第四轮、第五轮或专题评审，不为凑轮数提前冻结。

真实暂停可以在第二轮作为新产品能力单独评估；若采纳，第三轮必须明确状态、计时与持久化方案。本轮已有“收起”仍只表示页面收起，不能把继续计时改称暂停。

## 本轮回答的问题

LifeIndex 的主场景是短时间记录自己的生活，随后能按准确日期回看。今天页首先帮助用户完成眼下动作；健康、专注和记账承接各领域的深入查看。它不新增待办系统、生活总分、健康推断、银行连接或云服务。

本轮给出三个有实际结构差异的候选，每个均有轻量可运行原型。设计推荐 **A「日序」**，由总协调及独立审核决定是否选入第二轮。参考依据见 [体验研究](RESEARCH.md)，独立意见见 [R1 审核](REVIEW_R1.md)，固定任务及边界见 [执行约定](../../project/V4_EXECUTION_BRIEF.md)。

使用 Impeccable、Emil Design Engineering 和 mobile-native 的手动参考。没有运行 Impeccable launcher、engine、browser bridge 或 hooks。仓库不存在 `PRODUCT.md`/`DESIGN.md`，本轮以最新用户目标、执行约定与既有数据安全约束为依据，现有源码仅作为工程事实来源；不虚构缺失文档。

### 可操作范围与未完成范围

本轮可以切换顶层页面；从首页进入记账、体重、运动输入；切换收支与分类；提交合成表单；查看与切换习惯完成；开始合成专注、收起到今天再返回；打开月报并恢复返回来源与页面滚动；切换主题及空/读取失败场景。C 的“添一条记录”有真实类型选择，不能用跳到记账冒充通用新增。

本轮计时读数是标明的固定合成值，输入只完成方向级确认，尚未实现真实计时、完整校验、保存失败、全部历史/删除/恢复交互和键盘细节。指向第二轮的预览入口会明确提示其范围，不把它们当成产品完成证据。第二轮必须替换这些预览说明，完成固定任务及全状态可操作原型。

## 三个世界与结构取舍

方向来源经过七种具体结构推导：每日安排页、身体指标仪表、家庭收支账页、日期索引册、专注计时器、分区资料目录、生活杂志目录。它们分别对应行动、测量、分类、时间和检索，不把“生活索引”简单画成书本，也不以三种配色代替结构选择。

| 对比 | A · 日序 | B · 坐标 | C · 生活书页 |
| --- | --- | --- | --- |
| 首页先回答 | 现在可以做什么，今天做过什么 | 各个领域的当前数值是什么 | 这一天发生过什么 |
| 第一层 | 日期、真实简要概览、三个明确录入入口 | 三个不同领域的指标区及时间标签 | 周日期条、当前日期的记录入口 |
| 第二层 | 运行专注状态条、习惯独立完成控件；闲置专注随后 | 专注状态、快速记录、习惯 | 按发生时间分节的记录 |
| 第三层 | 当天真实记录与领域回看 | 近七日专注与最近记录 | 当天习惯与专注入口 |
| 视觉语言 | 暖白底、深墨绿、细分隔、任务型排版 | 深蓝底、荧黄绿动作色、数字密度较高 | 暖纸色、棕红、书页标题和时间边线 |
| 主题理由 | 白天记账与健康记录适合清晰、温和底色；晚间有独立深色变量 | 晚间快速回看可采用深色，但也提供完整浅色 | 让少量个人记录有阅读节奏；深色减少夜间亮度 |
| 识别点 | 记录、当前行动、完成状态的层级不同 | 不同领域并列对照，明确来源和周期 | 日期及纵向时间顺序拥有主导地位 |
| 强项 | T1–T3 入口早且固定，今日习惯较早可见 | 一眼比较领域状态，适合已有丰富记录的人 | 回看富有节奏，合成样本不用同构卡片拼装 |
| 实际代价 | 要控制专注色块大小，避免重新遮挡习惯 | 首次使用会出现三个空指标，行动位置晚于 A | 习惯被历史内容推到屏外，T2/T3 多一步类型选择 |
| 本轮意见 | 推荐推进 | 完整备选，不采用其首页主结构 | 不推荐作为首页，保留日期分节纪律 |

推荐 A 是因为固定任务与当下记录机制更吻合，不是因为绿色更高级。A 从 B 保留“数值必有周期和状态”的纪律，从 C 保留“日期归属明确”的纪律，不混用三套外观。

### A「日序」的首屏契约

1. 页头只保留 LifeIndex 品牌和带文字的设置；分区标题只出现一次。
2. 日期与当天简要概览不生成健康评价；月报入口有可见文字。
3. 记一笔、记体重、记运动三个独立入口位于可变长习惯列表之前，标签不靠用户猜测图标。
4. 运行中的专注以紧凑状态条位于习惯前；闲置专注入口位于习惯后。底栏始终可进入专注。运行时显示“继续专注”，收起只改变页面，不暂停时间。
5. 习惯名称进入详情，右侧独立 44px 圆钮完成/撤销。完成状态同时用图形和可访问属性表达。
6. 当天记录在后面；只有已持久化实体进入记录列表，当前运行会话不混入完成统计。

推荐不用首页全屏背景照片。它会争夺本已有限的行动空间，影响金额与状态识别；原创几何图形只出现在专注区，装饰没有按钮造型，也不表达虚构进度。后续如专注沉浸页需要背景，必须服从对比度、离线与包体积预算。

## 导航与领域布局

移动端四个稳定入口：今天、健康、专注、记账。设置移到页头，固定显示“齿轮＋设置”，不是仅图标；桌面使用左侧导航，设置位于底部。四导航能给高频领域更清晰的触控空间，而设置仍从每个主页一次点按可达。

从首页寻找备份的固定脚本为“设置 → 导出备份/从备份恢复”，两次点按到达相应动作。当前只证明页面路径与可见命名，不声称真人发现性研究已经通过。

| 页面 | 主信息与入口 | 第二轮必须补齐 |
| --- | --- | --- |
| 今天 | 当日概览、三种记录、专注状态、习惯、真实记录 | 六习惯及长内容、部分领域失败、返回来源、跨日 |
| 健康 | 体重主值与真实趋势、运动次数/时长、习惯 | 各自历史、目标、创建/修改/删除、归档与日历；不保留意义重叠的总加号 |
| 专注 | 预设时长、开始、剩余/已用/目标、收起继续 | 真实时钟语义、提前结束、放弃、保存失败与恢复；真实暂停是否加入将在第二轮单独决策 |
| 记账 | 月收支概要、当天流水、日历与报表明确入口 | 日期选择、分类层级、完整 CRUD、异日保存回看、报表与流水上下文 |
| 报表 | 明确月份、支出分类、真实明细 | 期间切换与返回恢复；无预算数据时不显示剩余预算 |
| 设置 | 外观、分类、备份、恢复、关于 | 文件选择取消、校验错误、预览、替换确认、失败保持当前数据 |

记账默认布局倾向流水优先，日历成为明确的日期选择入口。此决定尚待第二轮用 T6 与日期回看场景复查，不能因为当前 8px 日历金额过小就删除日期检索能力。

## 数据与状态原则

三方向使用相同合成事实：当天一笔咖啡支出、一次已保存专注、一条体重记录、两个计划习惯；本月收支汇总和历史图表也明确为合成样本。领域内记账流水只包含交易，不混入专注或健康记录。

实际实现以实体保存的`localDate`归属业务日；交易/运动使用`occurredAt`，体重使用`measuredAt`，习惯使用`completedAt`，专注使用明确的开始/完成时间及保存状态。不能用插入数据库的时间统一替代发生时间。跨日专注计入哪一日，在第三轮架构契约中明确。时间不足的记录只显示日期，不生成精确时刻。

| 状态 | 方向级表达 | 后续验收责任 |
| --- | --- | --- |
| 空 | 描述尚未记录及下一步，不画假曲线、不显示生活得分 | R2逐页面原型，M4数据库空值验证 |
| 加载 | 保留页面骨架和分区；仅延迟明显时显示读取状态 | R2状态矩阵，M4避免瞬时加载闪烁 |
| 读取失败 | 明确数据未被清空，可重试；不用0替代错误 | 本轮已有合成失败视图，R2补部分领域失败 |
| 写入中 | 动作有状态、限制重复提交；既有记录仍可辨认 | R2原型、M4事务及并发验证 |
| 保存失败 | 保留全部输入，说明下一步；不提前出现成功记录 | R2/R4 |
| 成功 | 简短回执、数据刷新；异日记录可直接查看 | R2/R4 |
| 未保存离开 | 保留编辑或明确放弃；不能仅靠关闭手势丢输入 | R2/R4 |
| 专注恢复 | 收起不暂停；后台返回由时间计算，失败保留会话 | R3状态契约、M4/QA测试 |
| 恢复备份 | 选择→完整验证→内容预览→明确确认替换→原子恢复 | R2完整流程与M4数据安全测试 |
