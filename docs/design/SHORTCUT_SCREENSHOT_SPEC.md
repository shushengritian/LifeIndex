## 已确定范围

支付详情页手动触发 → 截图 OCR → 提取金额和交易时间 → 快捷指令内选择收支、一级/二级分类 → 打开 LifeIndex 草稿 → 用户确认保存。

保持 PWA、IndexedDB、本地优先；不引入云端 AI、后台数据库、支付监听或原生 App。借鉴其他 App 的入口与核对流程，不调用其他记账 App 专属动作。

## 快捷指令动作配置蓝图

动作名称可能随系统语言/版本不同。实际模板需在目标 iPhone 验证。

1. 接收共享的单张图片；有图片则使用该图片，无输入则执行“截屏 / Take Screenshot”。保存运行开始时间供明确的回退选择使用。
2. “从图像中提取文本 / Extract Text from Image”。不加“存储到相簿”、云端 API 或完整 OCR 日志。用户自行截图分享时，相册原图由用户管理，指令不自动删除。
3. 用“替换文本”“分割文本”“重复每一项”“匹配文本”“如果”规范化换行、全角符号与金额格式，按下面规则形成候选。
4. 单一明确实付候选作为草稿；多个候选用“从列表中选取”显示金额及必要的字段标签，并提供手动输入。没有候选时“询问输入”；始终允许修正，不做默默猜测。
5. 提取并核对交易时间；缺失/歧义时提供“使用本次运行时间”或“手动选择日期时间”。旧图片不自动补今天。
6. 收支类型默认支出但可切换；从配置中的有效一级分类“从列表中选取”。有子级时再选二级（含“不细分”），没有子级则跳过。传递最终分类的稳定 ID，不按显示名称匹配。
7. 为本次草稿生成小写 UUID actionId；重试同一草稿沿用该 ID。金额转规范十进制文本，时间格式化为带时区偏移的 ISO 8601；各参数单独 URL 编码。
8. 用“打开 URL”进入 LifeIndex 的 `#/action/add-transaction` 草稿确认页。只传最小字段，不传图片、完整识别文本、订单号或支付账号。保存成功前不得提示“记账成功”。

建议入口：在支付详情页轻点背面触发，或支持机型的操作按钮。用户需要在 iPhone 设置中绑定，网页不能代配系统按键。不要先切到快捷指令 App 再截屏，否则可能截到错误页面。若浮层遮挡、截图受限或截图为空，改用系统截图分享单张图片，或手动输入。

## 金额与时间规则

- 首版人民币单笔收支；遇到外币、退款、转账、待支付、失败/关闭订单，要求用户核对类型和金额，不自动当成已付款支出。
- 优先“实付金额 / 实际支付 / 支付金额”等字段的同一行或紧邻下一行；无明确实付字段时才使用带币种金额候选。OCR 文本不保证包含字号或准确坐标，因此不能承诺选择页面最大字体。
- 排除标注为优惠、原价、余额、手续费的数值作为默认实付；不能取第一个、最大或所有数字之和。订单号不是金额。千分位与小数须严格校验，无法确定的 O/0 等错误交给用户，不静默替换。
- 时间优先“支付时间 / 交易时间 / 付款时间”，不以订单创建时间、截图文件时间或状态栏时钟冒充交易时间。
- 完整日期时间可解析；只有时分、只有日期、昨天/今天、缺少年份、多个冲突时间、未来时间时要求补全或确认。无法推断的秒数/时区不能声称来自截图；无时区按设备本地时间解释并展示供核对。
- 截图 OCR 仅见当前可见内容，不能读取页面外字段、滚动整页或微信/支付宝后台交易数据。使用支付详情页比支付成功简页更可能得到完整时间。

## 分类配置与数据边界

快捷指令不能实时读网页 IndexedDB。拟由 LifeIndex 导出专用分类配置 JSON，用户通过 Files 选取并让模板加载；不把私人分类写进公共 iCloud 指令模板。配置只含版本、收支域、分类 ID、parentId、显示名、有效状态，不含账目和金额。默认可存“我的 iPhone”；选择 iCloud Drive 会同步该配置，需明确告知。

更改分类后重新导出并替换配置；执行期间配置损坏或没有有效分类，停止并提示更新，不用分类名猜 ID。App 收到请求后必须再次查当前数据库：不存在、归档或跨收支域时禁止直接保存，并允许补选或引导更新配置；不得退回任意“其他”。此恢复能力待开发。二级 ID 所属父级从数据库读取，不能信任 URL 提供的关系。

现有 parser 已接收 actionId、amount、categoryId、type、occurredAt、可选 note；不随意增加字段（当前 strict 校验会拒绝未知字段）。现有正式产品尚未实现本轮二级分类及 OCR 修正交互，不能直接拿 G4 内存样本 ID 生成正式链接。源时间是否回退先在快捷指令中明确核对，若 App 需要展示该来源，另定义兼容协议再实现。

fragment 不随 HTTP 请求发送，但仍可能进入浏览器历史、剪贴板或分享记录；不得称完全无泄漏风险。沿用草稿消费后的 URL 脱敏设计并测试，不记录完整 URL。截图与识别文本仅用于指令运行，不主动持久化或上传。

关键验证门槛：打开 HTTPS 链接不保证唤起主屏幕 PWA，可能进入 Safari。必须确认记账写入的是用户日常使用的同一账本；若隔离，禁止将“Safari 成功”当作 PWA 成功，另设计显式转交/导入或统一入口并请用户确认。网页不能强制选择 iOS 存储容器。

## 开发与交付顺序

1. 用脱敏/合成支付详情样本验证系统 OCR 输出及字段规则，先覆盖微信、支付宝常见页面；不承诺适配所有版本。
2. 定义分类配置导出契约，完成二级分类真实 ID、校验、确认页修正和旧链接兼容；按 G4 审核门禁推进生产实现。
3. 制作真正的快捷指令模板，验证每个动作、取消和失败分支；在 Apple 环境生成可安装分享产物，不虚构 iCloud 链接。
4. 安装说明覆盖添加模板、选择分类文件、轻点背面/操作按钮绑定、权限拒绝后的恢复以及分类更新。
5. 自动测试字段规范化、整数分转换、UUID 去重、分类校验；真机验 OCR/触发/分享/URL 跳转/同库写入与离线。浏览器模拟不能代替这些系统专项。
6. 所有门槛满足后再开放“添加到快捷指令”；本轮不部署、不改生产代码。

验收样本至少包含：实付/原价/优惠同屏，多金额，订单号，只有状态栏时间，完整支付时间，跨日旧截图，不清晰图片，空图，外币/退款/未支付，失效分类配置，取消，重复打开同一请求，同图重新运行（新 actionId 不能自动防此类重复，应核对或另加重复提示），首次联网安装、后续离线、Safari 与主屏幕 PWA 账本一致性。
