# 戒烟 UI 与交互 — Review 0.1

**状态：** 2026-09-14 用户批准实现；产品 UI 已接入本地数据，独立设计原型仍仅作参考。默认最近七天，可展开月历；计划起点/基线固定，原因可编辑，支持吸烟/烟瘾记录更正。尚未发布。
**对应：** [PRD](../product/SMOKING_CESSATION_PRD.md)、[版本计划](../../V2_1_PLAN.md)。

## 1. 视觉与信息架构

继承 V2 的米白/深绿灰背景、鼠尾草绿强调色、系统字体和单层卡片，不增加品牌吉祥物、肺部仪表、奖励商城、破功红屏或强迫完成的进度环。浅色/深色同等完整，默认跟随已有外观设置。卡片圆角 20 px、页面间距 16–20 px、正文 16 px、辅助文字 12–13 px，操作区至少 44 × 44 px。

健康保留现有顺序：体重 → 运动 → **戒烟（新）** → 习惯。首次只占一行；有计划后为紧凑卡片，显示时长语义和今日状态，进入详情处理日志/帮助。详情是健康的子页而不是底部新 Tab，返回时恢复健康滚动位置。

```text
健康
  戒烟卡片 → 戒烟详情
               ├─ 开始/管理计划
               ├─ 截至现在未吸烟（快照）
               ├─ 我想抽烟 → 短时帮助 → 保存感受
               ├─ 记录吸烟 → 时间/支数/诱因
               ├─ 回顾日历 → 某天确认/事件更正
               └─ 寻求支持 → 外部官方资源
```

## 2. 逐屏规格

| 画面 | 内容与主要动作 | 特殊状态 |
| --- | --- | --- |
| U1 健康入口 | 一张卡片，时间、今日状态；整行“查看戒烟”与 + 入口 | 未启用为“开始计划”；隐藏后可从健康 + 恢复；读取失败单独重试 |
| U2 戒烟详情 | 返回健康、右上管理；主数字（距开始/最近记录吸烟）、截至现在按钮、我想抽烟；下方 7 天、估算、支持 | 不把开始时长叫真实无烟时长；无基线隐藏金额，零记录显示引导 |
| U3 开始计划 | 开始时间默认现在；可折叠“原因与节省估算”；取消/开始 | 未来开始为准备中，确认前不创建记录；脏表单退出提示；记录后起点/基线冻结 |
| U4 烟瘾帮助 | “先给自己一点空间”；轻量 3 分钟计时、呼吸/喝水/转移注意力；诱因可选；缓解了/还想抽 | 非治疗计时；可跳过、结束；退出未保存不生成事件；不得自动写习惯或 Focus |
| U5 记录吸烟 | 支数、日期时间、可选诱因；温和说明；取消/保存记录 | 支数/日期校验，重复点不重复写；若同日有无烟确认说明将撤销，保存后可去历史更正 |
| U6 月历回顾 | 月份前后、周一开始、点击日期 → 日详情；底部文字图例 | ✓ 完整无烟、· 有吸烟、◐ 当日快照/过去待确认、— 未记录；形状+文字不只靠颜色 |
| U7 支持与计划管理 | 官方资源指引、非医疗说明；隐藏入口/结束本次/重新开始；历史计划列表 | 外链显式离开 App、联网、不附个人数据；结束/重启确认，历史永不自动删除 |

主界面最多两个高频动作并排：“截至现在未吸烟”“我想抽烟”，窄屏按宽度换行。吸烟记录是单独可辨认的次要行，不埋在多层菜单。原有体重/运动记录继续使用可访问的图标按钮，日期输入与同列输入等宽，不引入此前 V2 修复过的问题。

## 3. 交互状态

- 每日快照成功：按钮变为“已记录至 HH:mm”，可以更新快照或撤销；跨日变“待确认”，不会自动填满日历。
- 点过去日期：展示当日日确认与烟瘾/吸烟记录；无吸烟事件时才允许“确认全天未吸烟”。当前日期只提供快照；未来日期只展示不可记录说明。
- 保存吸烟：先确认数据，事务成功后才关闭；同日无烟确认被撤销。重新开始是独立选择，不随吸烟自动触发。
- 烟瘾休息：使用实际经过时间，不依赖后台定时器；本版未保存休息不承诺关闭/重载恢复。返回仍有页面内状态时按开始时刻重算；不播放后台音频、不震动或弹系统通知。
- 历史列表仅按时间展示与轻量编辑，不引入日记富文本、照片、地理位置。记录数量可分页，不一次加载多年全部事件。
- 底部表单使用已有 Sheet 的焦点管理、背景 inert、Esc/取消、脏表单与更新保护；保存失败输入不丢失。

## 4. 原型边界

原型是当前任务中的独立交互设计，所有状态仅内存、刷新还原，不写 IndexedDB、不联网、不发送日志内容、不操作生产 App。默认用合成的 2026-09-14 数据，可切换浅色/深色、健康/详情、已开始/未开始，供用户审核。

原型演示核心点击流、月历选择、快照与吸烟互斥、帮助结果、管理确认及表单校验。跨日/时区、真实持久化、迁移、离线 Service Worker、系统键盘、严格模态焦点循环等仍是开发阶段测试目标，不因原型可点而视为实现或真机通过。

原型不为未修改的体重/运动/习惯页面重新制作一套功能；那些区域只用于解释新增入口的位置。设计稿中“准备中”“读取/保存错误”等非默认状态同时由本规格定义。
