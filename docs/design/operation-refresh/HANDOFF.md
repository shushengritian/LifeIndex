| 批次 | 范围 | 关键验收 |

| I1 共用控件与返回契约 | 图标/短标签主动作、列表导航、节标题入口、触控与圆角状态；Sheet / ConfirmDialog / NavigationGuard | 关闭、取消、Escape、脏草稿、焦点回归、背景不可操作、导航位置不变 |

每批至少：修改依据 → 文件/组件清单 → 状态与事件契约 → 文档同步 → 最窄相关测试 → 截图/操作证据 → 剩余风险。验证结果不能由原型直接继承。

## 实现前必须明确的共用契约

- 「打开」使用链接/导航语义，「执行」使用按钮；底部导航继续常显文字，不用纯图标代替。
- 图标视觉尺寸与触控区域分离。除窄屏七列日历的受限宽度外，操作目标以至少 44 × 44 CSS px 为目标，主操作高度 48px；需要实际测量，不靠声明通过。
- 表单取消分未改动、已修改、正在保存三种情况；失败保留原输入；保存中锁定重复操作；无变化保存也不得悄悄创建重复记录。
- 返回到来源页的滚动位置与选中日期；保存到其他日期必须给可回看结果，不让记录看似消失。
- 减少动态效果模式关闭非必要动画；动画不决定业务提交时机。
- 颜色只是辅助手段：选择、完成、错误、归档同时有文字/图形/语义状态。
- 日志只包含固定事件、操作类型和状态，不输出金额、体重、备注、标题、记录内容或备份内容。
- 增强界面不改变存储格式；若实施过程中发现必须改变业务/schema，应停在设计决策，不隐式迁移。

## 生产验收与原型验收分开

原型可以验证操作可发现性、主次层级、流程衔接、模拟错误反馈、普通浏览器布局与焦点。

原型不能证明真实数据恢复、文件分享、离线持久化、SW 更新、iOS 后台计时、系统菜单、主屏幕安全区、实际软键盘或 VoiceOver 完整可用。上述项目需要生产实现后专项验证；尚未完成的 iPhone 检查不得标为通过。

最终设计决策由用户确认；工程实现与发布分别获得授权。设计代理和审核代理的一致意见不等于用户验收。
