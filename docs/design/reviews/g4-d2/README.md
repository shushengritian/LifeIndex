# G4 D2 · 键盘焦点与边界流程检查

2026-09-19。当前结论：本轮焦点修复与下表检查完成；原生 200% 放大、全应用最终独立审查仍待完成，G4 未通过整体验收。仍为隔离内存原型，无生产变更。

## 本轮修复

1. **重绘后焦点丢失**：修复前日历选日、分类使用中/已归档切换后 activeElement 为 BODY。新增 `g4-accessibility.js`，保存 DOM 的 data/id 标识，只在源控件已移除、焦点落到 BODY 且没有打开弹窗时恢复等价控件；没有等价项返回可聚焦主内容。不覆盖业务控制器已设置的焦点。
2. **弹窗键盘边界**：修复前保存按钮 Tab 后落到 BODY、首按钮 Shift+Tab 到 DIALOG。现在只在最上层现有弹窗的首尾循环；中间控件保留原生操作。当前 confirmation 在 editor 之后且后打开，DOM 顺序与打开顺序相同；未来改变弹窗结构须重新验证。

Safari 指针激活可能不触发按钮 focus，因此在点击捕获阶段记住来源。日志只记录固定恢复/循环事件，不写标识、日期、文本或数据。未修改 G3 样板、生产逻辑或数据库。

## 浏览器证据

| 路径 | 实测结果 |
| --- | --- |
| 金额 Tab / Shift+Tab | 金额→餐饮→金额；控件顺序可逆 |

| 修改金额后 Escape | 出现放弃确认，默认焦点“继续编辑” |

| 表单首尾循环 | 保存账目 Tab→关闭表单；关闭表单 Shift+Tab→保存账目 |
| 日历 Enter 选日 | 重绘后焦点仍在对应日期，不回 BODY；选空日期可继续新增 |
| 分类筛选/新增保存 | 筛选保留按钮焦点；保存后返回新增分类入口 |
| 三个运动分类全归档 | 新增运动无可选类型，输入时长后提交被阻止，明确引导设置创建/恢复 |
