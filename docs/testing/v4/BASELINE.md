## 可重复性能采集

命令：`./node_modules/.bin/playwright test --config playwright.performance.config.ts`。该独立测试配置使用 4184 生产预览、单 worker、Chromium 的 iPhone 13 视口、4 倍 CPU 降速、无网络降速、每次新上下文、禁用 Service Worker 缓存影响及减少动态效果。七个空库样本记录 FCP、数据就绪与新增账目编辑器显示延迟，并统计 dist 的 JavaScript/CSS gzip 字节。

另以六个每日习惯及三十笔合成账目记录首屏布局，检查高频入口是否被习惯列表推离首屏。该样本不包含用户数据。性能采集不代表真实 iPhone 性能或公网延迟。

初次九项采集测试全部通过（13.1 秒）。七个冷启动样本中位数：FCP 204 ms、首页数据就绪 1067.10 ms、记账编辑器显示 254.80 ms。全量 JavaScript gzip 222903 字节，CSS gzip 11374 字节；这是 Node gzip 的统一计算口径，与 Vite 打印值略有不同。

代表性内容布局初次使用禁用 Worker 的配置：390×664 CSS px，六个每日习惯、三十笔账目；“记一笔”顶部 y=784.69 px，文档高度 1229 px。独立审核发现图中存在“离线功能暂未就绪”横幅，要求排除这个比较混杂因素。

已补测正常 Worker 就绪状态（1 项通过，3.0 秒）：相同视口及合成数据，“记一笔”顶部 y=732.69 px，文档高度 1177 px，仍在首屏底部导航之后。后续布局对照使用这一正常态，不能把移除 52 px 的异常横幅算作改版收益。保留 [正常态截图](baseline/today-six-habits.png) 和 [Worker 禁用对照](baseline/today-six-habits-worker-blocked.png)。

固定预算后的复测九项通过（12.7 秒），完整七样本及 gzip 结果保存为 [性能 JSON](baseline/experience-profile.json)。保留 [旧版记账编辑器](baseline/expense-editor.png)，其可见键盘焦点是应保留的可访问性反馈，不当作视觉缺陷删除。

## 冻结预算（生产 UI 实现前）

| 指标 | 3.3 测量值 | 4.0 上限 |
| --- | --- | --- |
| 七样本 FCP 中位数 | 204 ms | 400 ms |
| 七样本首页数据就绪中位数 | 1067.10 ms | 1400 ms |
| 七样本账目编辑器显示中位数 | 254.80 ms | 350 ms |
| 全量 JavaScript gzip | 222903 B | 250 KiB |
| 全量 CSS gzip | 11374 B | 16 KiB |

预算允许新增界面语义和正常实验波动，不允许失败后静默提高。最终用同一配置、新上下文和同一数据口径复测；若发生环境故障，记录原因并重测，不丢弃不利有效样本。首屏出现和数据就绪分开计量；编辑器延迟包含定位、滚动、渲染及焦点交付。默认 reduced-motion 的测量只证明基础响应，正常动效另做视觉与交互检查。

性能测试文件通过附件输出 JSON，并保留首屏与编辑器截图。报告永久归档于本目录 `baseline/`，最终版本另存 `release/`，不得覆盖旧版测量。
