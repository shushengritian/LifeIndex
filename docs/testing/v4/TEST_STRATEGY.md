## 2. 合成数据、时间和隔离

所有测试使用独立浏览器context和测试专用数据库，不复用用户浏览器profile、storageState、真实导出或个人截图。新版数据库名从冻结契约获取，不硬编码旧库名为数据源。运行线上冒烟也用新context，写入只存在于该context的本地库；不向外部服务发送合成记录。

固定seed与fixture版本，每份记录使用符合schema的确定性UUID；fixture manifest另存 `qa-<类型>-<序号>` 标签和明确中文测试标题，标签不冒充实体ID。随机边界测试记录seed；业务时间来自指定baseDate和offset，不靠执行顺序碰巧落在同一天。断言以精确记录集合/数值为准，不仅检查“成功”提示。

| 数据集 | 内容和目的 | 使用范围 |
| --- | --- | --- |
| F0 空业务库 | 首次创建新版库，仅允许必要默认分类/偏好；无交易、健康记录、习惯或会话 | 首启、空状态、首条新增、空库性能 |
| F1 代表数据 | 6个当天有效习惯（2已完成/4待做），30笔交易（24支出/6收入，覆盖今天/昨天/本月不同日期），30条体重、12次运动、14次已完成专注；分类覆盖不同领域 | 核心任务、首屏、正常数据性能、报告/趋势 |
| F2 边界事实 | 零记录日、同日多次、相同时间、不同UTC offset、月末/闰日、未来日期拒绝输入、跨午夜专注、归档分类、名称/备注边界长度 | 日期、排序、引用、编辑与报表；不自动加入性能数据集 |
| F3 长历史 | 10000笔交易、730条体重、500次运动、24个习惯和最多365日完成、1000次已完成专注，按确定规则分布 | 长列表、查询范围、统计准确、内存/交互专项；另七样本ready≤2000ms、首次支出editor≤350ms中位数 |

每个fixture生成manifest：fixtureVersion、seed、baseDate、timezone、表数量、预期汇总、关键引用和文件hash。金额/体重用整数最小单位；期望总数与报告数由独立简单算式或固定清单核对，不能调用被测汇总函数生成“期望”。

功能时间测试使用可注入时钟/可控浏览器时钟，覆盖当地日切换和不同offset。**性能测试不冻结performance.now、requestAnimationFrame或调度器**；以当次捕获的当地baseDate构造相同规模数据，计时依赖真实单调时钟。整组跨本地午夜影响fixture归属时记录原因、保留整组结果并重跑完整组，不能仅替换慢样本。

代表数据性能预置在同源最小HTML页面中通过测试拦截器完成，该页面不加载应用JS/CSS/字体或注册SW。写入新版声明schema与数据后再导航应用，避免先开完整应用seed导致“冷启动”已暖。没有暴露到生产的fixture接口。F0不预建业务库；两种数据集分别报告，不能混算。

库隔离另做一项合成哨兵验证：同一测试context预置一个无关库及可选旧名空壳哨兵，新版启动/保存/恢复后内容不变，且未调用删除/清理它。此项证明边界，不要求旧数据兼容，不访问真实旧库。

### 日期精度专项（R3-A04）

交易、体重、运动只收集日期，schema固定timePrecision=day且拒绝occurredAt/measuredAt；详情及轨迹不得显示虚构分钟。验证新建今天、补记过去、仅改数值、修改日期、跨午夜打开草稿、导入异时区日期这六种路径；日期不被createdAt或本机导入日重写。当日习惯完成有真实completedAt，历史补记只有day精度，唯一性/重试不改变事实时间。

今日轨迹必须包括habitChecks；时刻事实与仅日期事实分组，后者明确未记录具体时刻。同日两条体重用不同createdAt、相同createdAt不同UUID、修改早录入条目等fixture证明稳定规则；补记旧日期不替换最新日。“刚刚留下的”只表达录入顺序，不把createdAt当发生时间。

UTC offset由DateSelection捕获：新建默认日/显式改日期时采样；仅改数值保留原offset。草稿跨午夜仍保存可见所选日；习惯昨日条目在零点后完成是day精度，不把完成迁至今日。focus固定instant，其localDate只与startedAt匹配，跨日endedAt允许不同日。领域查询与备份使用同一精度union；伪造day.completedAt或day.measuredAt等字段须拒绝。

### 共享边界专项（R3-A03）

逐项在字段组件、命令直调和备份验证中执行相同有效/无效边界：体重与目标为999/1000/1000000/1000001克；分类名trim后0/1/30/31、习惯0/1/40/41、专注0/1/80/81、备注0/1000/1001 UTF-16 code units。加入emoji验证前后端都按code units计数。金额至少验证1/9999999999及上下越界，运动1/1440分钟及0/1441/小数。金额输入3位小数、体重公斤输入4位小数拒绝，不默默舍入。

默认19个分类ID及所有fixture均须符合固定UUID v4规范；未知实体iconKey拒绝，已定11项可往返导出恢复，UI动作write/play/pause不混入实体枚举。初始化偏好四键及revision存在，缺少键的备份拒绝；删除未用默认分类后重开不重新播种。原型cat-N等内存ID不当作生产schema证据。

分类重新启用覆盖成功、同scope active规范名冲突、先改归档名后重试；冲突保持归档及所有历史引用，不合并、不覆盖。跨scope同名可启用。Today计划专项用1个应做已完成+1个非计划已完成：scheduledCount=1、scheduledCompletedCount=1、completedCount=2，进度为1/1而非2/1；所有事实在轨迹。完成后items稳定创建顺序不改变。历史日只有事实，不回推当前计划分母。

### 中央全局记录的上下文矩阵

R4采用中央“留一笔→选择类型”；选择层只是动作路由，不算可编辑界面。完成选择后主字段真实可编辑且自动获得焦点，不能用一排静态类型按钮算达到U02。中央动词与笔形图标表达录入，不沿用加号作为中心动作。

对三个录入类型都执行下表。至少覆盖今天的当前/回看、健康历史、习惯详情、专注运行/暂停、记账异日、月报异月、设置等所有允许打开全局记录的来源；设计如明确某状态不开放入口，应有可解释且可测试的禁用/隐藏规则。

| 退出方式 | 要保留/改变什么 | 数据断言 |
| --- | --- | --- |
| 类型选择层取消 | 原分区、当前/回看模式、日期/月、筛选、滚动、触发器焦点完全保持 | 无业务写入 |
| 空编辑器取消 | 同上；按冻结设计回来源或选择层，路径清楚且不循环 | 无业务写入 |
| 脏表单→继续编辑 | 原值、错误、光标/合理焦点和编辑器滚动保持 | 无业务写入 |
| 脏表单→放弃 | 关闭所有相关模态，回原上下文一次；不残留背景inert | 无业务写入 |
| 同日保存 | 成功后回来源，原范围不跳动；相关查询更新 | 一次精确写入，不因回来源再执行 |
| 异日保存 | 明确保存日期及“查看记录”；原浏览日期/月不被默改；回看打开正确实体/日期 | 记录归属所选业务日，原日期统计不误增 |
| 保存失败/重试 | 留在同一草稿，全部字段保留，错误可获焦；重试成功后正常返回 | 失败未造成部分写入，成功仅一条 |
| 主/次级确认Escape及返回 | 首次只关闭最上层确认；焦点回下层原按钮；编辑器仍在且值不变 | 无额外写入 |
| 来源条目消失 | 回到稳定节标题/页面h1，不把焦点扔到body或已卸载元素 | 不能为恢复导航创建替代业务记录 |

D方向已给定日期规则：中央全局记录打开时捕获设备当地今天；只有明确的“记下这一天”领域动作继承可见选定日；编辑使用记录日。日期输入始终可见。强制跨域用例为finance选异日→today/health→中央记录，仍应默认今天，取消/保存不能把finance的选择泄漏给其他领域。保存后DOM重建也须按稳定语义key解析并恢复焦点，不能只focus已卸载节点。若“查看记录”离开来源，应可通过明确返回回到来源浏览会话，而非每次重建首页。两个返回动作之间不依赖暗藏手势。

| 记录新增/编辑 | 合法/非法输入、默认值、依赖读取失败、保存中、保存失败、重试、成功、未保存退出；切实体不混草稿 |
| 记录详情/删除 | 只读打开关闭、编辑入口、删除确认/取消/忙碌/失败/成功、不存在实体；回来源焦点正确 |

| 备份导出/恢复 | 见第7节；文件菜单取消、预览/确认每层都有可返回路径 |
| 内部命令重放 | 稳定commandId/entityId、同意图重试只写一次、陈旧entity revision拒绝覆盖；新版不提供外部动作链接或回执表 |

故障注入优先用服务/时钟依赖注入和可控制Promise。慢读/慢写人工延迟只用于状态测试，必须覆盖“重试”“连点”“离开”“更新”；不能流入性能fixture。真实IndexedDB测试需要至少一次transaction abort、约束冲突和恢复中途异常，不能只mock一个reject证明回滚。所有异常后核对数据库，而不仅看toast。

范围专项必须放入刻意越界的fixture：本月财务包含上月/下月哨兵；本周运动包含前周/后周哨兵；最近体重先按localDate，再按createdAt/id，今天补记旧日期不改变最近日；同日趋势取最后录入，编辑不重置createdAt；报告月份改变同步影响标题、汇总、类别和明细。周一起始；新写未来事实时间拒绝，备份按源exportedAt验证，异时区恢复不重划日期；不能靠当前seed恰好都在同范围漏检。

跨context并发专项：两个页面同时完成同一习惯只得到一条；同时启动专注最多一个未结束；pause/resume/finish/reconcile使用陈旧revision时不能覆盖已完成/丢弃事实；恢复与其他写命令的竞态按冻结契约阻止或串行处理。UI锁只保护当前组件，数据库不变量必须在真实事务中成立。

重放专项覆盖删除后的旧意图：三种记录、分类、习惯、focus.start分别执行create成功→另一context删除/丢弃→同commandId及旧expectedRevision再次create，须EntityConflict且实体仍不存在。同ID仍在且相同lastCommandId/payload的立即重试返回已有实体，不增revision。无关写入使未提交create的expectedRevision过期时，保留草稿、明确冲突，禁止静默刷新stamp。习惯完成→撤销→旧完成重放须被父habit revision拒绝；父revision变化不能重置scheduleEffectiveFrom。同desired无变化不增revision。以上均验证meta而不只看界面。

公开接口检查按架构TS签名执行：读结果为Snapshot，缺实体为null，失败抛固定code不伪造空；getAll给values及各key revision；实体编辑只接收明确Input、忽略字段的策略为拒绝而非任意patch。observe首次/更新/失败/退订均可控制；第一页/下一页与总数一致，跨generation游标拒绝。RecordView五个kind保留各自单位与引用，五个Today区域分别失败/恢复不会互相替换数据。

| --- | --- |
| 全页面正常/空/主要错误、全部编辑器与确认层 | 320×568、390×664、430×932、768×1024、1440×900 × light/dark；至少Chromium全矩阵，WebKit同矩阵做布局/关键触点检查 |
| 核心T1–T6、上下文与数据流程 | Chromium桌面/390短屏、WebKit390短屏；两主题；320px重跑记录/日期导航/退出确认 |
| 200%文字 | 五种宽度×两主题，至少所有页面和编辑器；两引擎，检查换行、滚动、触点与遮挡 |
| 动效 | 正常/reduced-motion；全部会阻塞输入、改变焦点或进出视图的动画，快速打开/关闭/返回 |
| 长内容 | 中文长标题、无空格长串、边界备注、负号/大额金额、长分类、多行错误；不截断关键动作 |
| 字体 | 字体加载前/后、字体请求失败、离线命中、数字/中文fallback混排；不因字体交换失去控件或内容 |

200%文字不得只设置root font-size后宣称覆盖所有px字号。可执行自动化方法：先采样文本控件/文本容器的原计算字号和固定行高，再一次性按2倍覆写（不能边读边改造成子元素重复放大），保持viewport和布局宽度不变；记录为“200%文字压力模拟”。另由独立浏览器检查支持的原生文字/页面缩放并如实记录方法。CDP视觉缩放或deviceScaleFactor改变不等于文字重排，不能替代该检查；物理iPhone文本设置另行待用户验证。

每个关键控件验证稳定布局的实际命中框≥44×44，不能只看CSS min-height；检查中心及内边缘hit test，避免透明覆盖层和邻项遮挡。输入计算字号≥16px，label关联正确，单位可读。中央记录与相邻导航各有独立命中区域，开模态后背景不可Tab进入。

独立键盘脚本：Tab顺序、Enter/Space激活、Escape只关闭顶层、焦点陷阱、关闭后归还触发器、错误提示可获焦、屏幕阅读名称无重复歧义。原生select/date input在两引擎中的选择与提交需操作验证；键盘出现后的真实iOS视口不在无设备时冒称通过。

R4整行动作与详情必须为独立可命中的兄弟控件，无嵌套button；整行用Enter/Space完成，再次激活撤销，文字明确状态。按下后拖走/滚动不误触，失败保持原状态且可重试；成功焦点留在同一语义位置并可见，不被底栏覆盖。详情操作只读，不能冒泡调用整行命令。完成不依赖加号/对号/复选框或颜色，轻推方案不是本次默认生产能力。

axe扫描范围含每个页面、类型选择、三类编辑器、详情、错误及二级确认，serious/critical为零；其他等级逐条处理并留理由。人工补查对比度、颜色非唯一语义、焦点可见、图表文本替代、固定栏遮挡、拖拽/手势是否有按钮替代。扫描通过不等于完整WCAG认证。

本地字体和原创素材可以服务新风格。R2目前Manrope.ttf为164700B，仅是原型资产观察，不自动进入生产预算；最终记录许可证、实际生产文件、raw/压缩/实际请求大小。字体/图片不计入JS/CSS额度，但必须计入总首屏请求与预缓存资源清单，不能用类别排除隐藏重量。

## 6. 新版性能协议

### R3提交的绝对上限

下表是已收敛的唯一R3提案，需独立签定后实施；执行后不能为失败提高上限或改采集定义。

| 指标 | 上限提案 | 每组判断 |
| --- | --- | --- |
| FCP | 400ms | 七样本中位数；只代表首个内容，不替代ready |
| Today首屏真正ready | 1400ms | 七样本中位数，F0/F1分别判断 |
| expense/weight/activity编辑器可输入 | 各350ms | 每类各七样本，F0/F1分别判断，不能三类混算 |
| 类型选择层可操作（若有） | 350ms | 记录首次全局动作至类型可选；防止把等待藏在第一步 |
| 所有生产JS gzip | 250KiB（256000B） | 所有生产JS文件求和，包含SW及其生产脚本 |
| 所有生产CSS gzip | 16KiB（16384B） | 所有生产CSS文件求和 |

无旧版性能对比要求。F3长历史另七样本，ready中位数≤2000ms、首次支出editor≤350ms。正常动效和资源加载观察也必须完成；字体/图像不另设任意体积硬上限，但其真实加载影响必须进入ready/交互结果，资源清单不能遗漏。中位数通过不能遮蔽单个核心路径无法完成；保留所有样本、min/max及失败，极端值由独立QA归因而非删除。

### 场景和样本组织

**F0/F1 × 三种编辑器 × 七次独立context = 42条主采样。** 每条只打开一种编辑器，避免先开记账把共享代码暖好后冒称体重冷打开。每条都测FCP、ready及该编辑器；若有中央选择层，另记chooserReady。六组分别出七样本及中位数，ready不得混成42样本大中位数隐藏某组波动。另加F3长历史七样本为专项组，总49条，不与42条主组混算。

1. 固定生产build及其commit、Node/包管理器/Playwright/浏览器版本；报告工作区是否干净、构建base path和资源manifest/hash。停止会抢占CPU的测试/构建，记录机器型号、电源、系统和时间；没有机器指标时标缺失，不捏造。
2. 使用Chromium、iPhone13设备配置并明确覆盖viewport为390×664 CSS px、locale zh-CN、timezone Asia/Shanghai、CPU4×、无网络降速、reduced-motion reduce、SW block、单worker、retries0。DPR/触控/UA从设备配置记录为具体值。
3. 每样本新context；建立CDP session后先设置 `Emulation.setCPUThrottlingRate {rate:4}`。测试fixture预置不请求应用资源。开始应用导航时才进入主计时。
4. 禁止性能测试使用开发server、HMR、Playwright clock冻结或特意预热资源。若应用真实空闲预取，应如实保留并记录资源时间线，测试不主动hover/焦点预热、不注入额外等待。
5. 使用实际用户路径：直接入口或中央记录→类型。点击前确认目标完整位于可见可交互区域，不让Playwright滚动后掩盖首屏不可达。选择层ready后立即进入类型选择，不人为等候预取完成；记录两次事件时间，等待人类选择的空隙不加进最终editor指标。
6. 收集原始Performance/资源事件、状态与焦点证据；结束计时后再验证真实输入值改变并做截图，避免截图/截图动画干扰主计时。关闭context，进入下一样本。
7. 有效慢样本不删除。环境事故保留失败组和原因，修正后重跑完整七样本组，不混用事故前后数据；功能错误是测试失败，不能标环境事故。不得使用CI的自动重试次数择优得分。

CPU4×及localhost是可复现诊断条件，不代表真实iPhone或公网延迟。WebKit不套CDP CPU降速；单独记录同设备视口功能与体验观察，不与Chromium数字混算。

### ready的准确含义

从同次navigation `performance.timeOrigin` 对应的0点计到以下条件首次共同满足，并在后续两帧保持：

- 新版库初始化/所需种子与主题读取结束，没有全局加载/错误遮挡。
- 首屏的导航、记录入口和首屏必需区域真实可用；首屏摘要、习惯、活动专注等各自查询为ready（可能为空），不能用任一区域的“暂无”代替整屏。
- 所有首屏写入触发器enabled；入口不处于inert、遮挡、不可点击转场或透明占位中。当前运行状态真实，不能用默认“无运行”抢先标记。
- 首屏文本/控件有稳定几何位置，下一帧内不会被仍在进行的布局动画推走；晚加载字体/素材的额外移动独立记录并核查。

R3的 `criticalReadyRegions` 固定为五个：shell（含theme、导航、中央记录与模式）、today-habits、today-finance、focus-runtime、today-records。默认今日概览的五区域均data-state=ready且真实初始化/读取完成；today-records在短屏位于折叠线下仍纳入，避免布局位置改变测量名单。完整历史/轨迹后续页及未打开编辑器可延迟。UI用 `data-state`/Performance marks等可观察契约表达真实状态。QA同时断言控件、区域状态与hit test，不能只相信一个自报mark。把上述区域改成占位或移出名单以满足门槛必须重新评审，不能静默改“关键区域”名单。

采集在浏览器内计算时间戳。Playwright等待仅用于取得结果，不把其轮询/进程通信耗时当业务ready时间。缺失mark、区域失败或条件未达成直接失败，不能填0或把timeout后时刻当成功。FCP从paint entry独立取得，大于0；它可能属于启动占位，不用来推断ready。

字体策略如果是swap，ready不强制等不影响可用性的所有字体，但同时记录 `document.fonts.ready`、关键目标加载前后矩形和字体请求；任何晚交换导致文字不可读、操作遮挡或点击目标移动必须解决。字体若是首屏意义不可替代的关键资源，则必须纳入对应criticalReadyRegion，而不是排除出ready。

### 编辑器的准确含义

使用capture listener记录真实pointerdown或Enter/Space激活的浏览器内时间戳，不以 `page.evaluate()`发起前的宿主时间做起点。中央流程以最终类型选择的实际激活事件作为editor起点，第一步选择层单独计时；直接入口以唯一激活事件为起点。没有人工输入字符时间混入。

结束条件必须同时满足并稳定至下一帧：

- 正确类型编辑器已可见、不是背景/inert层，必要编辑依赖已可用；不是仅出现通用loading壳。
- 主字段为真实可编辑控件，enabled、非readOnly、有可见label/单位，`document.activeElement`为该字段；三类主字段分别为金额、体重值、运动时长；如设计需要变化，必须在本轮独立重新审核此协议。
- 字段与主要取消/保存动作可触达，焦点不在隐藏副本、类型按钮或被确认层遮挡处；没有等候装饰动画结束的状态。
- 时间戳由浏览器内条件观察+requestAnimationFrame取得，自动化侧断言不向结束时间加入轮询延迟。

取得结束时间后通过键盘输入固定合法字符，断言控件值与编辑状态确实变化，然后取消并核对没有误写。测试不调用field.focus来替应用交付焦点；不能只用 `.fill()` 成功证明自动获焦。另测键盘激活路径和正常动效路径。主预算采用真实触控/鼠标激活，键盘路径分别报告，不混样本。

### 资源与产物

递归遍历生产dist内所有JS/CSS，逐文件Node gzip后求和，包含SW和其脚本；排除source map、测试报告、设计原型等非生产文件需列明。读取生产manifest/请求清单，检查没有应用脚本搬到不计数后缀或inline大块规避预算。

同时输出：每文件raw/gzip，首屏实际request/transfer/encodedBody/decodedBody（注明localhost是否启用压缩），字体/图片/SVG/manifest大小，首次交互新增资源，预缓存总量。JS/CSS gzip额度和真实传输量是两个口径，不直接相除当加载改善。

现有 `tests/performance/experience-profile.spec.ts` 只等记账空态、只测一个dialog可见、不验证focus，且使用旧库/选择器；它须由开发者按新协议改造后才可执行4.0门槛。不能直接运行旧脚本并把通过结果填到U11。

报告JSON至少含：schemaVersion、runId、commit/buildHash/basePath、protocolVersion、fixtureVersion/seed/baseDate、浏览器/机器/视口/DPR/CPU设置、全部样本及顺序、FCP/ready/chooser/editor时间、关键区域状态、输入类型/获焦状态、资源清单、组中位数/min/max、失败/排除及原因、预算版本和截图相对路径。报告不能含个人输入；fixture内容已知也不把完整数据库转存进日志。

## 7. 新版数据、备份与离线

### 新数据契约

验证新库只建冻结的表/索引，不探测/迁移/清空无关库；新建失败保留错误和重试，不自动重建。字段、范围、唯一性、引用、同域分类、整数单位和日期逻辑在repository命令层测试；绕过UI调用非法命令也须拒绝。每条拒绝后逐表快照相等。

新版以后自身升级要有测试，但本次不要求旧版本迁移。选择新schema1时，不得为了制造“升级覆盖”编写与产品无关迁移；如4.0开发中需要提升新版schema，则按真实路径验证。

### 专注的确定R3输入与数值用例

R3采用running/paused/completed，paused携带pendingCompletion时投影为awaiting-save。默认25分钟、开始日localDate归属、暂停不计时、收起不改变运行/暂停/待保存状态。确切字段和两阶段命令见[架构第6节](../../design/v4/ARCHITECTURE.md#6-r3专注状态时间与原子性提案)。至少执行以下有明确期望值的用例：

| 用例 | 操作与精确期望 |
| --- | --- |
| 多段暂停 | 25分钟目标，运行10000ms→暂停60000ms→继续运行20000ms→提前结束；只保存30000ms，暂停不计入 |
| 小段精度 | 运行400ms/暂停/运行400ms/暂停/运行400ms→结束；累计1200ms，不能逐段取整成0；显示秒与统计格式按统一规则 |
| 互补秒显示 | 25分钟目标在23999ms单一快照下显示已用23、剩余1477，合计1500；禁止两端独立floor造成1499 |
| 目标到期 | 已累计10000ms，剩1490000ms；再运行超过剩余60000ms才返回，timer完成仍恰1500000ms，endedAt为原有效终点 |
| 暂停刷新 | paused累计10000ms，刷新/关闭后推进一天再回来；累计仍10000ms，恢复后新运行段起点为恢复命令时刻 |
| 跨午夜 | 前日23:55开始，暂停跨日后次日完成；属于开始日，详情显示两日；今日已保存统计不误收，运行区仍可回到会话 |
| 自然完成幂等 | 两上下文同时reconcile、连续触发visibility、重复同token finalize；只一条completed、一次时长统计 |
| prepare失败 | 注入第一事务失败，原持久状态保持；本地意图终点冻结、可重试、未保存退出提示；不得显示已完成 |
| finalize失败 | prepare已成功后注入第二事务失败；重开库仍为paused+pending，时长固定、不能resume；重试同token后恰一条completed |
| 暂停焦点 | 键盘/触控pause后语义控制位变为resume，重渲染仍获焦；resume后反向同理，不落body；原暂停期间时长不变 |
| 命令冲突 | pause/resume/finish持旧revision与另一上下文竞争；重读当前状态，不能重新开始段或覆盖完成事实 |
| 时钟倒跳 | now早于当前段起点/已提交转移时刻；拒绝写负时长/逆序状态，保留记录并给可恢复错误；时间校正后重试 |
| 正向长间隔 | 关闭时running，设备时间已过目标；按设备墙钟封顶完成。记录无法判断离线期间改时的产品限制，不伪称可信物理时间 |
| 完成输入失败保持 | 标题/备注编辑失败保留字符串；自动完成失败保留token/终点，不逐秒重试，不入已保存统计 |
| 完成详情与删除 | 详情只读；仅修改标题/分类/备注；remove仅接受completed，discard仅接受未结束；删除失败原记录及统计保持，确认成功才移除 |

备份恢复另覆盖running、普通paused、pendingCompletion、completed各一合法样本及互斥字段/目标时长/唯一未结束等非法组合。恢复确认前不能reconcile导入数据；原子替换成功后controller按恢复规则处理，pending沿原token而不是重开计时。源/目标未结束会话分别计数并说明，目标当前会话会被替换需明确确认，可取消回专注；不得把所有未完成会话从完整备份悄悄排除。目标原会话在预览期间自然完成引发revision变化，确认必须PreviewStale。

### 备份恢复

R3采用lifeindex-v4-backup/formatVersion1/schemaVersion1、50MiB、15分钟TTL、八业务表全量替换，meta不从文件接受。执行：

1. F1导出→完整解析→规范化内容/计数核对→空的新测试库恢复→逐条等价；导出metadata允许变化，不能影响业务等价。
2. 对格式、版本、JSON、字段类型、数值范围、数量、主键、引用、习惯日唯一、活动专注数量逐一破坏，全部在任何写入前拒绝；旧/未知文件只测拒绝零写，不要求兼容。
3. 选择文件取消、验证失败、预览取消、过期、重复确认、确认层取消，各自核对全部新版表不变，焦点归还正确。TTL用单调时间；设备墙钟倒跳后实际经过15分钟仍过期，不能靠更改日期延长token。
4. 用户确认之前不写；确认后在替换中途注入真实事务失败（已完成若干删除/插入之后abort），关闭并重新打开库，所有原表逐记录保持；不能只比总数。
5. 预览绑定目标generation+revision。另一context新增/编辑/删除/改偏好后确认，必须PreviewStale且逐表/meta不变，提示重新预览。恢复先提交时，另一context旧草稿expectedGeneration必须GenerationConflict，保留输入可查看/复制，不能自动切新generation重提。token被消费后不能二次重放；恢复成功后query/主题/会话一致，旧草稿不能冒充当前有效草稿。
6. 每个业务写事务含meta；对照两种顺序分别测试“写先→预览过期”和“恢复先→旧写拒绝”。导出与恢复竞争，只能得到完整旧代或完整新代快照。服务锁/按钮busy不作为跨context正确性的唯一证据；恢复失败meta也精确回滚。
7. 系统分享/下载失败或取消不显示虚假的最终保存地点；对象URL释放；文件名/正文/token不进日志或缓存。真实Files/iCloud系统菜单仍属物理设备待确认项。

快照比较先等应用后台事务稳定，对表按主键规范化排序后比较。不得忽略刚好变化的字段以“让回滚测试过”；允许变化的元数据必须事先列入明确契约，并与业务事务责任区分。

### 离线与更新

在新context联网首次安装，等待SW ready及实际controller接管、外壳资源缓存完成，再断网刷新。六项核心任务、各个惰性路由/编辑器、报表、设置与新版备份UI都能打开；创建/编辑后刷新仍保留。先在线打开所有路由再断网不算证明“首次安装即缓存必要路由”，须至少一组离线路由此前未访问。

检查CacheStorage只含已允许静态外壳（包括采用的本地字体/图像），无业务查询结果、记录JSON、备份Blob；IndexedDB中记录变化不依赖网络。无第三方字体/CDN才不会在离线时悄悄丢字形。

更新专项使用两个可追溯本地生产构建A/B，缓存A后提供B：发现waiting→明确更新动作→激活→版本B。脏表单/待提交写操作时不得强制刷新；放弃或完成后才按流程更新；失败保留现有应用与草稿。专注的已持久状态在重载后按选定时钟契约恢复。A/B是新版应用更新测试，不是3.x兼容承诺。

Chromium/WebKit均执行其支持的SW/离线能力；若某自动化引擎能力确实受限，保存实际错误、范围和替代验证方式，不沿用旧skip冒充本次通过，不宣称真实iPhone已验证。

## 8. 隐私、工程与Pages验证

隐私用F6执行创建/编辑/失败/详情/导出/恢复，捕获console、网络请求URL/body、storage/cache与附件。断言日志仅含固定事件和允许枚举，不含备注/标题/金额/体重/日期/ID/备份正文/token；校验logger运行时过滤，不只依赖TypeScript类型。检查网络仅有允许静态同源资源，不能向分析/云服务发记录。静态产物和Git差异不含凭据、用户数据、真实导出、临时构建或测试下载。

最终源码阶段运行以下既有命令入口，但只有相关suite已改为新版契约后才具有4.0意义：

```sh
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
pnpm exec playwright test --config playwright.performance.config.ts
```

每批先跑最窄相关文件，不重复全量消耗代替修复；收口时完整运行。记录实际命令、时间、源码、通过/失败/跳过数量，保留首个失败、重试与最终结果。现有功能CI自动重试不会洗掉不稳定问题；未解释的不稳定核心路径不签收。

Pages沿用既有站点与工作流：构建验证→部署→线上冒烟。生产以配置的base path构建，核对main/merge提交、构建artifact、部署版本一致。性能环境与最终base path有差异时补根/子路径资源验证，不把旧preview当部署证据。

线上只在独立context执行：实际版本4.0.0、根入口/深链接/刷新、JS/CSS/字体/图像/manifest/worker无404、核心新建与回看、刷新持久化、离线shell及惰性页、无外部数据请求。使用 `LIFEINDEX_DEPLOYED_URL` 显式指定实际Pages URL，再运行 `pnpm test:deployed`；不能只验证HTTP200。保存工作流/部署URL、SHA、线上版本和独立测试报告。

回退方案区分应用源码与新版IndexedDB：回滚静态应用不能自动回滚数据库。新命名空间避免修改无关库，但新版当前用户记录仍需要保管；不得用清库当回退。版本说明和操作文档同步这一限制。
