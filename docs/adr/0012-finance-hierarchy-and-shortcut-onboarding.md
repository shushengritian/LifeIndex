# ADR-0012 · 二级分类与快捷指令安装引导

2026-09-19。用户提出需求，纳入 G4 设计；细则和完整原型待审核，不是生产开发、迁移或发布授权。

## 设计决定

- 导航交换为：今天、健康、专注、记账、设置。不改路由 ID 或默认首页。
- 收入/支出最多两级，专注与运动仍一级；可只选一级（“不细分”）。
- 新分类归属于同收支类型、使用中的根分类；禁止跨域和第三级。按用户后续反馈，管理首页只显示一级，点击一级进入其二级列表，在其中新增名字/图标，父级从页面上下文固定，不再提供父级下拉。已有分类父级锁定，移动不在本次范围。
- 账目只引用一个稳定分类 ID，显示“一级 / 二级”。老分类均保留为根级，不猜测老记录属于哪一子级；改名同步路径，不改金额/日期。
- 归档一级使其二级不再供新增使用，但不改写子级自己的归档状态；恢复一级不恢复被单独归档的子级。历史编辑可保留原归档分类。
- 分类管理引用数为直接引用数；未来按一级统计需合并直接记录与子级记录且每条只计一次。正式 schema/备份兼容和迁移测试在生产开发前设计，本轮不动真实库。

## 快捷指令

最新决定：用户已确认“识别当前支付页面金额与时间→快捷指令选择一级/二级分类→打开 App 保存”。以截图加系统 OCR 和本地规则实现识别方向，不引入云端 AI；这是对旧的纯手填方案的替代。详见 [截图快捷记账方案](../design/SHORTCUT_SCREENSHOT_SPEC.md)。以下早期评估仅保留历史，当前流程以此决定为准。

2026-09-19 补充评估：用户希望在指令内完成分类选择、最好完全不打开 App。可将收支及一级/二级分类选择前移到指令，再携带稳定分类 ID 打开确认页；这仍是待实现方案，需要解决私有分类配置、新增/归档后模板更新以及浏览器/PWA 存储上下文一致性。以下原拟“进入 App 后选分类”流程不再视为已确定首发方案。

当前纯 PWA、IndexedDB、应用壳 service worker 没有供快捷指令后台直接写入账本的通道。原生 App Intent 可后台执行，但需要原生实现及数据共享/分发设计；云端接口需要新的认证、隐私与服务端架构。两者均需另行授权，不能仅靠下载指令实现。文件暂存后导入不等于即时记账。待用户提供确切“记账本”App 链接后再核对其实际能力，不冒认参照产品。

依据：[Apple AppIntent supportedModes](https://developer.apple.com/documentation/appintents/appintent/supportedmodes)（支持后台动作）；[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)（客户端同源存储）。上述 LifeIndex 限制来自当前本地架构，不是所有网页后台能力的通用否定。

设置“其他”增加“快捷记账”：未来提供已配置指令的共享链接。现有 D1“快捷入口”是收到请求后的确认/失败/去重状态模拟，不是安装页。

旧提案（已被上方最新决定替代）：手动输入金额后进入 App 选分类。当前首发方向包含系统 OCR，手填仅作失败回退；仍不含支付监听、后台写入或云服务。

当前 `actionParser.ts` 的 add-transaction 必须带 categoryId，ActionPage 没有分类编辑表单。因此省略分类、到 App 中补选属于待实现的协议与页面扩展，不能宣称线上已支持。需要兼容旧链接、actionId 去重、校验、显式确认、完成后脱敏清理；金额/备注置于 fragment 路由而非发送至托管站点的查询字符串，日志不得记录完整 URL 或内容。

Apple 支持 iCloud 链接和文件分享；用户在 iPhone 上查看并确认添加。优先使用有效共享链接，按钮叫“添加到快捷指令”，网页不静默安装。共享模板不带用户真实记录或私有分类列表。

正式开放前：制作真实指令→生成共享链接→验证协议、分类与重复提交→iPhone 检查打开的浏览器/PWA 上下文与日常账本一致。快捷指令不能直接写网页 IndexedDB；若落入不同存储上下文，必须解决或明确限制，不能以安装成功代替记账成功。

原型安装按钮明确“待提供”并禁用，没有虚构下载文件或 iCloud 链接。

参考：[Apple 分享快捷指令](https://support.apple.com/en-il/guide/shortcuts/apdf01f8c054/ios)，2026-09-19 检查。
