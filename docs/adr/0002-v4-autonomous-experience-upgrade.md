# ADR 0002：LifeIndex 4.0 全面体验升级

日期：2026-09-28。状态：升级范围及自主执行已获用户批准；具体设计方案待三轮正式评审。

## 最新用户修订：独立设计新版

用户在执行期间明确要求：“不用考虑旧版，直接设计新版”。因此 4.0 的信息架构、导航、交互、页面和组件从新版使用场景出发，不承袭旧版界面或原始设想。“对比旧版全部不退步、至少三项相对改善”不再作为验收条件。已完成的 3.3 测量仅作工程背景存档，不继续扩大旧版研究。

六项任务保留为新版核心场景覆盖；验收改为明确的绝对要求：录入容易发现且两次点按内可编辑、状态清楚、完整流程可操作、布局与可访问性合格、性能预算及数据安全验证通过。第三轮在实施前冻结新版架构和可重复性能指标。

可靠代码能否复用由新版方案决定，不作为先决条件；需要调整领域或数据状态时，由架构明确契约并测试，不能仅因旧版不存在就否定新设计。本地优先、零新增费用和部署证据要求仍有效。

用户进一步明确“也不用必须三轮就定稿，可以多讨论几轮”。因此三轮仅为最低讨论要求。第三轮之后仍有影响体验、可实现性或验收的问题时，继续专题评审和修订；只有问题得到验证解决、独立审核支持后才冻结。新增轮次必须有具体问题、证据、修改与复查，不以轮数本身证明质量。

用户随后补充“也不用考虑历史数据”“大胆尝试，大胆设计”。历史数据迁移、旧备份格式兼容和旧 schema 复用不再是交付要求；可为新体验重新定义实体、状态和独立数据库。忽略历史兼容不要求执行无关的设备数据清理；若采用新库名，旧库不参与新版初始化和验收。新版自身的写入正确性、备份验证、原子恢复和错误恢复仍需验证。

设计增加新一轮挑战探索。A「日序」只是候选，允许更大胆的构图、颜色、图形、动效与交互后重新选向；不把“成熟”误解为只能保守微调。是否定稿依据真实原型和独立审查，轮次按实际问题增加。

2026-09-28用户继续否定传统加号/对号按钮的设计惯性。已打开第四轮动作专题：整行回应、完成纸签、轻推留痕三种可操作比较稿，根协调主推整行回应；全局记录改为“留一笔”。这是动作范围、文案和完成反馈的重设，不将旧方向签收当作新控件批准；详见[R4](../design/v4/ROUND_4_CONTROLS.md)。

## 背景与授权

用户已提交完整启动目标，明确授权研究、设计定稿、架构调整、实现、测试、提交、PR、合并和既有 GitHub Pages 部署，由团队在约定范围内自主决策。此前仅设计阶段的限制不再阻止本次产品实现与发布。Impeccable 可执行引擎及 hooks 的单独限制仍然有效。

当前生产版本 3.3.0；启动源码 `48cf37a`。开发使用 `codex/lifeindex-v4` 分支，保留启动前的工具安装与项目准备文档。不覆盖用户无关改动。

## 决策

- 全面升级今天、健康与习惯、专注、记账与报表、设置与备份的视觉与交互。可以调整导航、布局、文案、组件、图标、动效和背景元素；旧视觉及演示数据不构成约束。
- 保持本地优先、IndexedDB 主数据源、静态 PWA 与应用外壳缓存。领域和存储设计服务新版体验；无需为 3.3 数据或备份提供兼容路径。新版备份恢复仍先完整验证、再原子写入，失败保持新版数据不变。
- 先研究 5–8 个产品，再完成三轮有异议、回应、修订及复查的设计讨论；定稿前不进入生产界面实现。
- 八个职责按主代理加最多三个工作代理调度；方案/代码作者不能自行签署独立审核或验收。
- 插件、Skill、素材、额外 API 和新增部署资源不产生新增费用。图像和图标必须许可清晰或原创。
- “超过 80% APP”为品质愿景；签收依据为任务基线、完整状态、视觉系统、可访问性、性能、数据安全和独立证据，不虚构市场排名。
- 用户不再参与日常决策。本次发布以 Chromium/WebKit 与线上验证作为技术门槛，物理 iPhone 验收仍标记待用户实际执行并确认。

## 结果与发布边界

发布目标仍为 `https://shushengritian.github.io/LifeIndex/`，不扩展到付费资源、其他域名或公开本地设计服务。测试只用合成数据及隔离上下文；凭据、真实记录和备份不进 Git。

完成需关联同一待发布源码的检查、独立审查、Pages 工作流和实际线上验证。推送、构建或启动工作流不能代替部署完成。代码回退与数据库回退分开记录。
