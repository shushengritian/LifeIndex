# ADR-0009：健康中的轻量戒烟子域

**状态：** Accepted — 2026-09-14 用户要求开始实现。技术冻结见 [CESSATION_V3](../architecture/CESSATION_V3.md)，本地实现不等于发布授权。
**日期：** 2026-09-14

## 背景

V2 的健康包含体重、运动和习惯。用户新增戒烟需求，但要求保持轻量并先审 UI。戒烟涉及独立开始时间、烟瘾/吸烟事件、无烟日确认以及敏感记录，不能靠一个通用习惯打卡完整表达。

## 决定

- 健康内增加可隐藏入口与详情，底部五个目的地不变；不覆盖/改写既有 Habit。
- 一次仅一个未结束计划；保存历史，吸烟不自动删除计划、不清零历史。
- 使用本地 IndexedDB 新增计划、日确认、事件三个存储；schema/backup V3 已冻结，保留旧九表，完整恢复覆盖十二表。
- “未记录”“截至现在未吸烟”“完整无烟日”“有吸烟记录”明确区分；不宣称医学证实的持续戒断。
- 专业支持采用明确的外部资源入口；无隐式传参、嵌入式第三方、AI、用药指导或自动账本写入。
- 仅在用户通过 G1 后进入开发文档冻结与实现；发布许可和版本验收另按 V2.1 计划执行。

## 替代方案

只新增“戒烟习惯”最省代码，但无法表达烟瘾事件、部分日与完整日的差异；完整戒烟管理平台则超出用户需要。选择小型独立子域，仅复用视觉组件、日期/日志/存储/备份基础设施。

## 后果

UI 保持简单，但新增数据必须进入完整备份和原子恢复；升级不可通过清空 IndexedDB 完成。收益估算不是健康测量或真实账目。计划固定 IANA 时区，未来计划取消为空区间；明确结束后才允许新建，不能隐式结束当前计划。当前仅本地实现，不能写成已上线能力。
