# Ocean 候选：系统与 iPhone 验收

状态：开发候选，非上线公告。当前已推送开发分支 `codex/g5-ocean-implementation`，候选提交 `f71fe7f`；正式 main/Pages 尚未发布本次重设计。不要在现有线上旧版本执行以下步骤后，将结果记为新候选通过。

## 开始前的必要确认

1. 用户确认是否允许在这台 Mac 添加并运行 LifeIndex 测试快捷指令；只用合成截图和测试分类，不修改原有指令。开启快捷指令 iCloud 同步时，候选可能同步至其他设备。未确认前不安装。
2. 记录用户的 iOS 版本，以及平时从 Safari 还是主屏幕图标进入 LifeIndex。
3. 新候选可用后，先在“设置 → 其他 → 关于 LifeIndex”核对最终发行版本；当前开发包仍为 2.1.1，不能仅凭此数字判定新版本已部署。

## 仍需系统验证的项目

| 项目 | 操作与通过标准 | 不通过时 |
| --- | --- | --- |
| 快捷指令安装与权限 | 经授权安装候选，用合成支付截图，确认取图/OCR、权限取消和重试都有明确结果 | 保存复现步骤，不发布安装入口 |
| 金额/时间核对 | 一张截图包含优惠前价、实付和交易时间；核对最终传给 App 的值。缺时间/识别失败应可人工纠正，不把当前时间伪装成交易时间 | 不保存错误草稿；修复规则或交互 |
| 一级/二级分类 | 从候选设置导出分类配置，在快捷指令内选收支、一级及二级/不细分；失效分类进入 App 后可重新选择 | 保留草稿，不自动写入无效分类 |
| Safari / 主屏幕账本 | 从平时使用的入口建立一条明确合成记录，快捷指令打开后确认能看到同一记录及分类。不能假定两者共享数据库 | 停止真实记账测试，记录入口差异；不清数据、不盲目导入覆盖 |
| 原生放大与读屏 | 开启系统/浏览器 200% 放大与 VoiceOver，检查主页、表单、确认框、分类和历史；无被遮挡关键操作，名称与焦点顺序明确 | 记录页面/控件，不能以320px或axe代替通过 |
| PWA / 离线 / 后台 | 添加主屏幕后检查安全区、键盘、滚动；联网打开一次后断网记录；后台再回到专注/三分钟休息，时间符合实际流逝 | 不清缓存或数据库来“修复”；记录系统和入口 |
