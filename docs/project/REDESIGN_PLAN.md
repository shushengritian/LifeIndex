## 4. 质量与发布标准

### 设计质量

- G2：J01–J10 每条流程定义正常/异常/取消及返回来源，不藏关键操作。
- G3：双主题、中文、长金额、图标语义和按钮处理态；可访问名称/对比度/触点可测量。
- G4：页面/状态覆盖表、真实可点击路径、320/390/430、200% 放大、键盘/焦点设计；明确原型无法模拟的系统行为。
- 浏览器 screenshot/视觉对照与自动化断言分别留证，不以测试绿色代替用户审美审核。

### 工程质量

- 分支使用 `codex/` 前缀，实施前重新核实工作区与用户改动；小步审查。推送仅在明确授权范围内，本轮不操作 Git 历史。
- 按仓库要求在关键逻辑/分支/状态变化添加解释性注释及隐私安全日志；禁止金额、健康数值、事项标题、备注、备份内容入日志。
- 每次变更更新相关文档并运行最窄有效测试；候选跑格式、lint、类型、单元/集成、浏览器 E2E、构建及相关视觉检查。准确记录命令、SHA、通过/失败/跳过数。
- 数据合成 fixture 覆盖旧 schema/备份、金额/本地日期、计时、打卡与戒烟。无 schema 改动仍验证升级后数据与语义不变。
- 恢复先校验后替换；失败事务不破坏现有库。代码回退不能恢复已被替换的数据，数据库回退不能靠换旧应用壳假装完成。

### G5 发布候选报告必填

版本/SHA、批准设计范围、完成与未完成、全部测试及视觉证据、缺陷等级与处置、真机设备与结果/待确认、schema/备份影响、备份要求、代码回退及数据恢复限制、发布权限。

推荐无 P0/P1 才发布；任何例外必须用户明确接受且说明影响，不私自降级问题。真机未完成时提交明确延期选择，不自行继承旧版本豁免。GitHub 推送、Actions 构建、Pages 部署、线上检查、用户客户端激活是不同状态。

授权发布后：记录 CI 和 deployment URL/SHA，线上验证路由、base、资产/manifest/SW、版本与关键流程；交付“等待更新提示→处理未保存输入→立即更新→查看版本”的手机说明，遇旧缓存查明状态，不能建议清空业务存储来解决普通更新问题。

| 本地数据暴露 | 原型/测试只用合成数据；隔离 origin；不提交个人数据/备份/构建产物 |
| 历史文档/缓存误导版本判断 | 本审计记录 SHA、发布、部署和客户端状态；历史不删改冒充当前 |
