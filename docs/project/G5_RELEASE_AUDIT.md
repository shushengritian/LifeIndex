## 发布顺序与不得绕过的边界

1. 修复 P0/P1 并完成针对性回归、独立复审。
2. 完成批准 G4 的最终视觉/交互、无障碍及迁移检查；实际未能验证的真机项需用户决定，不继承旧版本豁免。
3. 快捷模板不得仅凭签名开放安装；原生运行测试需添加候选，已向用户询问，不擅自操作系统权限或原有指令。
4. 冻结发布版本和文档，运行完整本地/CI 门槛。当前 package 仍为 2.1.1，尚未决定新的发布编号。
5. 经过授权的 Git 提交/推送、正常 Pages workflow、真实部署 URL/version/schema/base/smoke 验证，记录不可混淆的提交和运行编号。
6. 最终交付列出安装/更新、数据边界、已知限制和真机实际状态，再判断 Goal 是否完成。

本轮没有发布、修改远端设置或清空用户数据。没有选定许可证，不能代用户添加许可证。数据库 V4 上线后不能回滚到只理解 V3 的客户端。
