# LifeIndex 4.0 升级与回退复盘

归档日期：2026-09-29。结论：4.0完成了工程交付，但整体视觉未获得用户认可，已按要求撤回。当前产品和线上版本为 **3.3.0 Ocean**；保留4.0设计参考，不保留其应用实现或可运行原型。本文是复盘，不是重新启动4.0的计划。

## 经过与最终决定

用户希望全面升级UI与交互，允许自主决策、多角色协作、多轮讨论及自动部署；后续明确不受旧版设计和历史数据兼容限制，鼓励大胆设计，并质疑惯用的对号、加号按钮。

团队完成研究、四轮设计讨论，形成「日常调频」方向：整行习惯回应、笔形“留一笔”、暖纸色与深紫色视觉、本地字体和原创图形。随后实现全模块及独立数据层，完成代码、功能、布局、可访问性、性能和发布检查，部署4.0。

用户实际看到后评价“好丑”，明确要求回退3.3.0并部署、4.0不保留。回退完成后，用户补充要求保留设计文档，避免浪费可借鉴部分；应用代码继续删除。因此当前分支只恢复设计文档、静态截图和观察记录，历史实现仍可在Git历史中审计，不提供双版本入口。

## 工程结果与体验结果必须分开

4.0当时通过294项单元/集成、86项浏览器测试，云端及独立线上验证各8项；49个冷样本及2项交互观察满足冻结性能预算。这证明特定环境下的实现和验收结果，不证明审美符合用户喜好，也不证明超过市场80%的产品。

当前3.3回退重新通过252项单元/集成、91项浏览器测试，独立线上11项通过。浏览器与线上各有1项原有WebKit离线整页重载跳过，不能算通过。Pages构建、部署、线上验证三阶段均成功。实体iPhone仍未获得用户实测确认。

用户已经明确否决4.0整体视觉，这是产品结果。多角色内部同意、自动化通过、设计文档完整，都不能代替用户对审美的认可。

## Token消耗为何明显增大

以下是根据执行过程的定性判断；没有逐角色、逐轮输入/输出/推理Token和计费明细，不能给出准确占比或把目标累计计数等同账单。

- 工作从视觉探索扩大到全模块与独立数据层重建，叠加测试、文档、部署和最终回退，范围明显超过普通改版。
- 多角色多轮交接反复处理相同材料，长上下文和重复读取增加累计消耗。并行可能节省墙钟时间，不代表节省Token。
- 布局、焦点、离线更新、性能及截图工具问题触发多轮修订和复验；必要验证与重复验证没有充分区分。
- 工具曾输出过长日志，整份文档重复读取，发布阶段查询和说明过于频繁。等待本身不消耗推理Token，重复唤起分析和回复会消耗。
- 若使用高推理强度，复杂推理可能进一步增加消耗；本次缺少明细，不能认定模型设置是主要原因。

协调者的主要责任是范围与成本控制不足：用户授权自主推进，不等于应默认采用最重的团队和验证流程。最昂贵的失误是，在缺少用户审美校准的情况下将整套设计实现并发布，导致返工。

## 后续更合适的工作方式

以下是建议，尚不是已批准的新开发任务，也不自动增加强制确认流程。

1. 先明确改动范围与审美参照，选首页、主要录入页等2–3个关键页面验证方向；没有新授权不继续4.0。
2. 默认一名主设计加一名审核，先产出有实质差异的小样。仅在任务真正独立、输出能直接整合时增加角色。
3. 将审美判断与工程验收分开。若用户愿意参与，在少量高保真页面阶段确认偏好；若仍要求全自主，应依照明确参考约束小步实现、保留易回退能力，不把内部评审当用户认可。
4. 视觉改进尽量复用已可靠的业务逻辑，不因为重新设计页面就顺带重写数据层。新增范围单独说明价值和成本。
5. 代理只接收必要摘要、文件位置、约束和验收条件，避免每个角色继承完整长历史；一份共享决策记录代替重复叙述。
6. 先跑受影响检查，在里程碑执行必要完整验证；没有新改动、失败或风险，不反复跑同一套测试。日志保存文件，只读取摘要和失败段。
7. 发布等待采用合理间隔查询，减少无变化进度回复。阶段结束归档一次结果，保持下一轮上下文简短。
8. 开始前可约定成本或时间检查点；只有用户明确指定Token预算时才设置目标预算，不自行承诺固定节省比例。

## 可以留下什么

[设计档案](../design/v4/README.md)中的研究、不同方向、控件比较、状态设计、动效及评审异议可以作为候选素材；[实际截图](../releases/v4.0.0-screenshots/README.md)便于逐项判断喜欢和不喜欢的部分。用户尚未指定具体采用哪些元素，不能擅自把整行回应、配色或字体再次定为新版标准。

下一次从3.3.0当前产品出发，只选择明确有价值的局部改进。设计档案中的“冻结”“完成”“通过”均是历史描述，不恢复其实施效力。

## 收尾与边界

本次仅文档归档，不修改源码、依赖、数据库或部署。3.3与4.0数据库和备份不同，回退不会找回用户已清除的数据，也不进行自动删库或数据转换。当前没有待自动继续的4.0开发任务；后续按用户新的具体需求推进。
