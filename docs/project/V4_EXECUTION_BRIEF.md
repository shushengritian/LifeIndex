# LifeIndex 4.0 项目组与执行约定

日期：2026-09-28。状态：用户已提交 [启动提示词](V4_LAUNCH_PROMPT.md)，4.0 Goal 为 active，已进入基线核验和第一轮设计。完整自主执行授权见 [ADR 0002](../adr/0002-v4-autonomous-experience-upgrade.md)，实际进度以 [PLAN](../../PLAN.md) 为准。当前发布版本仍为 3.3.0。

最新用户修订：“不用考虑旧版，直接设计新版”。本约定据此改为新版独立设计及绝对标准验收。旧版测量仅存档，不限制新信息架构、导航、状态或组件；可靠代码是否复用由新版需要决定。

后续用户修订：“也不用考虑历史数据”“大胆尝试，大胆设计”。无需历史迁移、旧备份兼容或旧 schema；设计增加更鲜明的挑战方向，不因已有候选而收窄探索。新版自身的数据正确性、备份安全、本地优先和零新增费用继续有效。

## 执行模式

采用 **持续目标 Goal + 仓库内分阶段计划**。Goal 的完成条件是 4.0 通过独立验收、部署至既有站点，并获得线上验证证据。`PLAN.md` 记录阶段、决策和下一步。

官方说明区分了 Plan 的实施路径设计和 Goal 的跨轮结果追踪，因此这次准备好执行约定后，启动时使用 Goal 更适合“无需重复说继续”的需求。工作内部仍先规划、再设计、再实现；不把计划模式当作整个项目长期停留的状态。[OpenAI 关于 Plan 与 Goal 的说明](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)

Goal 仍受运行环境、权限和额度约束，不等同于无限后台运行。完成、用户中断或预算等停止条件应按实际状态处理；未完成不能标记为完成。[OpenAI Goals 文档](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)

## 项目组

这是 8 个职责角色，最多同时使用主代理和 3 个工作代理。后续角色在对应阶段启动，不为每个角色长期占用一个并发槽，也不创建额外用户任务。

| 角色 | 负责人 / 调度 | 责任和交付 | 主要工具与 Skill |
| --- | --- | --- | --- |
| 产品负责人、总协调 | 主代理 `/root` | 目标、范围、排期、证据、争议决策、集成与最终交付；维护 PLAN 和 ADR | Goal、Git、项目文档 |
| 体验研究员 | `/root/ui_research` | 5–8 个公开参考、事实与推断分离、任务对照和借鉴理由 | 网页研究、浏览器、ui-ux-pro-max |
| 设计总监、交互设计 | `/root/design_director` | 信息架构、任务流程、三个候选方向、最终视觉系统、页面和完整状态 | Impeccable 手册、Penpot、本地原型、emil-design-eng、mobile-native |

| 测试验收负责人 | 实现阶段启动 `qa_lead` | 独立测试、视觉比较、缺陷复现、回归与验收矩阵；开发作者不得代签 | Playwright、axe-core、verification-before-completion |

前三个工作角色已在准备阶段分别提交任务书和约束建议；这不计入正式设计的三轮讨论。

准备文档独立审核：`/root/design_reviewer` 已只读检查本文件与完整启动提示词，未发现启动时点、授权、职责、三轮讨论、成本、数据和发布证据方面的实质冲突。本结论只针对执行约定，不代表产品设计、代码或部署已经通过验收。

研究阶段：研究员、设计总监、审核员协作。定稿阶段可让研究员退出，换架构负责人。实现阶段：开发、测试、独立审查协作，架构负责人按需介入。发布阶段：发布、测试、审核协作。共享目录下明确文件所有权；Git 集成由总协调统一执行，避免并发操作同一分支或锁文件。

## 产品目标与范围

LifeIndex 4.0 是以 iPhone PWA 为主要场景的完整体验升级，覆盖今天、健康与习惯、专注、记账与报表、设置与备份。允许重组导航、交互和页面，旧视觉、旧组件和演示数据不作为设计约束。可靠业务逻辑可以复用，不以重写数量证明升级力度。

“超过市面上 80% APP”作为品质愿景；有限参考样本和内部打分不能证明市场百分位。实际以任务效率、完整状态、统一视觉、触摸体验、可访问性、离线可靠性和独立评审证据验收。

产品维持本地优先、IndexedDB 主数据源和应用外壳缓存，不引入业务后端、账号、云数据库、分析追踪。测试使用隔离上下文及合成数据。根据用户最新授权，新版不承担旧数据迁移和旧格式兼容，可采用独立数据库及新实体；无需主动清理旧库。新版内部的原子写入、备份校验和恢复失败保护仍是验收责任。重大设计与架构变化进入 ADR，并同步基线和 PLAN。

## 三轮正式讨论

用户最新授权：三轮是最低要求，没有第三轮必须定稿的期限。若仍有具体体验、实现或验收问题，继续增加专题轮次和修订，直至独立审核验证门槛满足。以下三轮为基础结构，不是自动放行流程。

每轮必须保存输入版本、研究依据、设计方案、独立异议、设计回应、具体修订、未解决事项及决议。不能把准备阶段建议、三个代理的各自回答或三次赞同计作三轮讨论。

| 轮次 | 讨论内容 | 输出与通过条件 |
| --- | --- | --- |
| 1：方向与任务 | 现状问题、5–8 个参考、六项高频任务；三个结构或视觉实质不同的低成本方向稿 | 对比和取舍、选定方向、导航与任务草案；研究、设计、审核至少完成一轮有回应的讨论 |
| 2：页面与状态 | 可操作原型、主要页面、深浅主题、窄屏与大屏、输入与异常状态 | 问题编号、修改前后证据；所有核心任务走得通，独立审核复查修改 |
| 3：定稿与实施 | 修订稿、设计变量、组件规范、架构意见、验收矩阵 | 消除阻断问题，冻结唯一设计系统；审核意见有具体解除条件，作者不能自行宣布审核通过 |

方案定稿由团队自主完成。审核员可以阻止有证据的缺陷进入下一阶段，但不能凭个人偏好无限重做。主代理裁决取舍并留证；硬性验收失败不得豁免。定稿后的重大变更重审受影响部分。

## 验收约定

| 维度 | 标准 | 证据 |
| --- | --- | --- |
| 完整覆盖 | 全部既有核心模块及新增、查看、编辑、删除、取消、恢复等适用流程；无死按钮、占位入口、伪数据统计 | 页面与流程矩阵、独立走查 |
| 操作效率 | 高频录入从首页不超过两次点按进入可编辑界面；今日习惯在其可见条目上一触完成；查看不意外写入 | 固定任务脚本与操作记录 |
| 核心任务 | 覆盖新增支出、记录体重、记录运动、专注完整生命周期、习惯完成/撤销、月报与返回上下文；按新版任务效率和准确性签收 | 固定合成数据、独立任务脚本和运行证据；不要求旧版比较 |
| 视觉系统 | 颜色、字号、间距、圆角、图标、按钮、表单、弹层、图表统一；主次清楚，摆脱未经设计的默认控件外观；装饰不妨碍阅读 | 设计规范、完整页面截图、独立设计评审 |
| 状态完整 | 按场景覆盖空、加载、成功、失败、禁用、长内容、未保存退出；失败保留输入，保存防重复，错误可恢复 | 状态矩阵、合成异常测试 |
| 响应与可访问性 | 320、390、430、768、1440 CSS px；深浅主题及 200% 文字放大；无非预期横向溢出和关键操作遮挡。关键触控区域至少 44×44 CSS px，输入字号至少 16px；可访问名称、焦点、键盘、对比度和减少动态效果偏好得到验证 | 截图、浏览器操作、axe 无严重/致命问题及人工补充检查；自动扫描不等于完整 WCAG 认证 |
| 性能 | 实现前以固定设备模拟、数据集、构建和运行方式冻结新版首屏、包体积和关键交互预算；实测不达标则优化 | 可重复测量及样本，不能用印象或测试耗时代替交互性能；旧版测量只提供工程参考 |
| 数据与离线 | 新版关键数据链路、备份解析验证后原子恢复、失败保留新版当前数据、离线关键流程和应用更新通过；不要求导入旧版数据 | 单元、集成、Chromium/WebKit 浏览器测试及新版备份样本 |
| 工程与发布 | 对应提交的格式、lint、类型、单元/集成、生产构建、端到端、独立审查通过；无未解决发布阻断缺陷；Pages 部署和线上冒烟通过 | 命令、提交、CI 运行链接、部署状态、线上版本和验证结果 |

真实 iPhone 测试继续单列为“待用户执行并确认”。本次自主发布以浏览器和 WebKit 验证为门槛，不把真实设备测试作为等待用户回来才能发布的前提，也不宣称真机通过。

## 里程碑和交付

1. **M0 启动与基线**：创建 Goal；核对 Git 工作区、工具、发布权限、现有测试；保护未提交工作；补充 4.0 范围 ADR、任务基线与 PLAN。
2. **M1 研究及第一轮**：参考矩阵、方向稿、任务模型、第一轮讨论记录。
3. **M2 原型及第二轮**：可运行的合成交互原型、页面与状态图、第二轮修订记录。
4. **M3 定稿及第三轮**：冻结设计、架构和组件契约、量化性能预算、完整验收矩阵。
5. **M4 实现与集成**：按模块完成小批量可审查修改，每批运行相关检查并更新文档；同步开展独立代码与视觉审查。
6. **M5 发布验收**：完整回归、移动和桌面走查、修复与复测、版本及发布说明、可回退应用提交。
7. **M6 部署与线上核验**：推送、PR/合并、既有 GitHub Pages 工作流、线上实际版本及独立冒烟，归档证据后才结束 Goal。

正式证据集中在 `docs/design/v4/`、`docs/testing/v4/` 和 `docs/releases/v4.0.0.md`。图片及设计素材记录来源与许可证；真实数据、密钥、备份和生成构建不进入仓库。

自动推进的授权以用户提交启动提示词生效。日常设计取舍、架构调整、免费依赖、小步提交、PR、合并和既有站点部署不再逐项询问。新付费支出、产品云服务、破坏真实数据、绕过权限或扩大外部发布对象均不在授权中。

遇到可修复故障先修复；工具缺失时使用满足同一验收标准的免费替代。外部额度、凭据、平台权限等确实阻断时，继续可独立完成的工作并保留断点；按 Goal 的实际生命周期报告状态，不伪造完成，不把审核失败静默改成通过。
